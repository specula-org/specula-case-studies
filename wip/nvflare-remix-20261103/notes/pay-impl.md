## Seed re-encoding decisions

| seed element | fine re-encoding |
|---|---|
| Init: tx registered, first waiter attached | `Register(si, ln)` driven by `pTaskCJ[si][ln].submission`; private `reg` flag; rest of the seed Init is the post-registration state |
| `pullPC` (SJ part) | PayRcv `rpc[p]` idle/sent/queued/done + `reqN[p]` |
| `pullPC` (CJ handler PC) | PaySrc `hpc[p]` (+ `hreq[p]` admitted key, `hidx[p]` = n-1 = request state by value) |
| `futureStarted` | implied by PULL message existence (`rpc = "sent"`); `queued` = unstarted pipeline future |
| `reply`/`replyNonce` slot | PAYLOAD_REPLY [status, value, nonce] for the request id; receiver consumes via `handled` |
| `index` read by reference | PULL body n (= index+1) |
| `confirmWire`, `consumerResult`, `consumerNonce` read at commit | RECEIVER_CONFIRM [ref, nonce, status] by value, captured in `fconf[t]` at HandleConfirmBegin |
| `cancelWire` (set of receivers) | RECEIVER_CANCEL [ref, status]; receiver identity from the sender process |
| booleans for nonce | nonce value `<<"nonce", c, l>>` |
| `shutdownSourcesPending` oracle | deleted. CJ `Shutdown` triggered by `pRunCJ[si][ln].state = "stopping"` (client_runner.py run finally); SJ `ShutdownSourceDownloads` triggered by `pWfSJ.dsShutdown` (server_runner.py:235-237), one atomic step over all sites |
| `AdvanceTime` (global clock, fault) | per-(c,l) CJ clock, bounded by `TimeLimit = IF "txTimeout" \in Faults THEN TxTimeout+1 ELSE 0` |
| `LoseConfirmation` | Net group (Net_L loses any kind) |
| seed fault classes | produce->payProduce, consumer->payConsumer, delete->payDelete, submit/executorStop->paySubmit, compute->payCompute, callback->payCallback, sourceFailure->sourceFailure; seed `shutdown` fault -> real trigger |
| (new) per-request timeout | `PullTimeout` (fault pullTimeout): retries exhausted -> download_failed, CANCEL iff index>0 |
| (new) source process gone | `PullSourceGone`: `CJGone(si, Desc.launch)` -> non-OK rc branch (no fault) |
| (new) unknown ref | `ServeUnknownRef`: INVALID_REQUEST from the current launch for a ref it never registered |
| (new) decode policy K12 | `SourceDownloadUnregister` (download_object return): status materialized/failed, `returned`, `fatal` = failed and not a typed local DownloadCancelled (cell.py:116-135 os._exit(1)) |

Port semantics: `pPayRcv.status = "materialized"` is set when download_completed returns (consumer holds the data, `ConsumerDownloadCompleted`), BEFORE the CONFIRM and before download_object returns; `returned` marks the return into FOBS decode. Rationale: Props `NoReleaseBeforeMaterialize` would otherwise flag the benign window CONFIRM(success) -> source settles/releases -> receiver unregisters. CommSJ should gate claim on `returned` (port request).

## 18:50 framework changes requested by the coordinator (design review)

- Wire ids: PULL `<<"pull", ref, n, k>>` (k = TIMEOUT retry number, fresh key per try; body adds `try`), CONFIRM/CANCEL `<<"confirm"|"cancel", ref, g>>` (g = descriptor generation = receiver attempt; the source still matches by body.ref only, so S11 ref-reuse semantics are preserved). No key is ever re-sent (harness and Mix assert NetKeep/NetOK).
- New PayRcv_F action `PullRetry` (TIMEOUT with retries left resends the same state; MaxPullTry = 2 under pullTimeout/netLoss, else 1; source default max_retries = 3); `PullTimeout` now means retries exhausted. Coarse `RetryPull`.
- PayRcv_F no longer reads `.lost`; uses `InInbox`. All `k \in Inbox(...)` under `\E k \in DOMAIN net` replaced by `InInbox`.
- `PullSourceGone` and coarse `FailCause` use `PeerFailureCJ` (real death or false suspicion under `transportFail`, i.e. H29 with the CJ alive).
- `settled` removed from `pPaySrc` (no reader outside PaySrc; settlement_complete stays private). PaySrc_C drops CompleteSettlement (10 actions now).
- Harness steps assert the same net discipline as the Mix (NetKeep, own kinds only, new messages not lost).

## 19:45-20:05 fidelity fixes found by the mix CE (H30 simulation)

The first payload-fine mix simulation (`pay_ff_h30_sim`: PaySrc=F, PayRcv=F, rest coarse, taskTimeout, 1 site, invariant NoSJFatalDecode) violated in 12-14 s. Triage of the first two CEs exposed two model defects (class (a)), both fixed:
1. Abort check first. `_download_object` checks `abort_signal.triggered` right after the request returns and before looking at rc/status (download_service.py:2226-2238). The seed's Consumer*Receive* actions and my PullSourceGone/PullTimeout ignored a triggered signal, so a request failure processed after the SJ's typed cancel still took the ordinary (fatal) path. Guard `st.sourceSignal[p] = "none"` added to ConsumerReceiveData/EOF/Error/ProducerError (deviation from the seed, anchored) and to PullRetry/PullTimeout/PullSourceGone.
2. Split-step atomicity of DownloadService.shutdown. WfSJ posts `pWfSJ.dsShutdown` and RunCJ posts `pRunCJ.dsDown`; the table teardown / signal publication live in PaySrc / PayRcv. In reality it is one synchronous call, so the CE window "flag set, signals not yet published, receiver proceeds" is an artifact. Fine variants now block every other own action while `DSShutdownPending(si, ln)` (PaySrc: dsDown /\ ~shutdown) or `SJShutdownPending` (PayRcv: dsShutdown /\ some site not yet shut). The chaotic env gained `DSDown`.
Coarse variants keep the permissive behavior (over-approximation; possible coarse-only spurious fatal exits are class (b)).
