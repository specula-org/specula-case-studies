## Issues Found

- **A second wait inherits terminal state from the previous syscall.** `PollFilesRegisterPoller` accepts `waitState = "returned"` and resets wake, result, and scan fields, but leaves `deadlineExpired` and `interruptPending` unchanged (`base.tla:2280-2315`). Timeout and signal actions set those flags (`base.tla:2405-2437`), while the terminal and mask-restore actions never clear them (`base.tla:2439-2523`). A review-only TLC check ran registration, timeout, return, mask restoration, and a second registration; the freshness invariant failed at depth 7 with 44 generated / 26 distinct states. Reset both flags when a new wait begins, or represent each syscall with a fresh wait instance, and retain a repeated-wait regression config.

- **A registered poll wait does not retain its snapshotted OFDs.** The brief states that poll/select snapshot OFD references before blocking (`modeling-brief.md:12`), and the shared-table path clones `Arc<dyn FileLike>` values into `PollFiles::Owned` (`kernel/core/src/syscall/poll.rs:96-101,124-155`). The model's `ofdRefs` counts slots, captured operations, deferred closes, epoll control, and local `Pollee::poll` state, but no `PollFiles` snapshot (`base.tla:443-455`). `PollFilesRegisterPoller` also records no captured OFD set (`base.tla:2280-2315`). A review-only TLC check reached `PollFilesRegisterPoller -> SysCloseRemove -> ClosedFileDrop` with the wait still registered and its OFD dead at depth 4 (12 generated / 9 distinct states). Model the per-wait captured set, count it in `ofdRefs`, and release it on every terminal path.

- **MC-8's exec/unshare race is excluded by construction.** The brief asks whether concurrent duplication or `close_range(CLOEXEC)` crosses the exec unshare boundary (`modeling-brief.md:174`). `ExecveWaitOtherThreadsExit` requires every modeled FD operation to be idle and changes the global `execPhase` to `quiesced` (`base.tla:456-465,1013-1028`); ordinary FD actions require `execPhase = "idle"`. Consequently no table mutation can occur between `ContextUnshareFiles` and `FileTableCloseFilesOnExec`, and the model has no old shared-table identity or external sharer. `MC_hunt_s1_exec.cfg:21-35` can vary flags only before exec, so it checks deterministic snapshot closure rather than the requested boundary race. Model old and private table identities plus an actor that may mutate the old shared table around the atomic clone/install step shown in `kernel/core/src/process/namespace/unshare.rs:18-28`.

- **Symmetry is used while checking a temporal property.** `MC.cfg` enables both `SYMMETRY Symmetry` and `MCOFDsNeverResurrect` (`MC.cfg:43-67`); the same combination appears in the lifetime and Scenario 1 configs. TLC completed but warned that symmetry reduction during liveness checking can miss violations. Remove symmetry from every config with `PROPERTIES`, or reformulate resurrection monotonicity as a history-backed safety invariant. The dedicated Scenario 2 and Scenario 4 liveness hunts already avoid symmetry and are not affected.

- **The neutral MC result is structurally narrow.** `MC.cfg` sets every non-FD budget and `MaxInterestLimit` to zero, and enables only five FD-lifecycle actions (`MC.cfg:23-37`). Callback, epoll, signal, wait, and topology invariants in that config are therefore vacuous. Focused configs provide broader coverage, but the neutral run should either enable a representative convergent action set or be labeled as an FD-lifecycle smoke check.

- **The strict source-annotation rule is not met for every generated block.** Base production logic is well annotated, and the instrumentation table supplies exact locations. However, MC controller actions such as `MCFileTableInsert` and many event-specific CASE arms in `Trace.ValidatePostState` have no local `file:line` citation (`MC.tla:120-188`; `Trace.tla:526-690`). Add local citations or an explicit machine-checkable reference from each wrapper/branch to its instrumentation row.

- **Validation rerun:** SANY parsed `base.tla`, `MC.tla`, and `Trace.tla` with exit 0. `MC.cfg` completed with 288 generated / 156 distinct states at depth 7. `Trace.cfg` completed with 37 generated / 36 distinct states at depth 36. A 50-trace base simulation completed with 1,731 generated states. An automated name audit found 74 base actions, 74 MC names, 74 trace names, and 74 instrumentation rows with empty set differences.
