# Local flock specification revision, 2026-10-05

This revision resolves R1–R6 from `review-specgen.md`. The review findings were
the only input to the revision. The approved brief and analysis were read-only
references, and the pinned implementation and installed validation method were
consulted only to implement those findings. Neither source tree, the brief,
the analysis nor the review was changed. No git command was run and no commit
was created.

These are local model and synthetic-trace checks explicitly requested for this
revision. They are not runtime trace convergence, an independent review of the
revised suite, or confirmation of an Asterinas defect.

## R1: Keep open's original reference through return

`base.tla:107` now models `FileTableInsert` cloning the Arc into the FD table
and retaining the original in `pending`. This follows pinned Asterinas
`kernel/core/src/syscall/open.rs:54-64`, especially the clone at line 63.
The insertion action brackets the existing table critical section, including
its release. `ArcPutOpen` (`base.tla:116`) follows `on_open` at lines 65–67.
`SysOpenReturn` (`base.tla:122`) follows that put and any synchronous destructor.
`ReferenceAccounting` counts the open-local reference through `PendingRefs`
(`base.tla:564-571`), both before and after insertion. MC increments `completed`
only at the explicit return events (`MC.tla:259`).

Trace dispatch and instrumentation include both new boundaries. Insertion now
requires both the FD assignment and the actual clone count. The R1 fixture
closes and drops ClosedFile on T2 before T1 puts its open reference. Its exact
post-state requires a 2-to-1 decrement, life `live`, and T2 at `closeReturn`.
Only T1's later put starts destruction. No invariant was weakened to admit it.

## R2: Serialize lookup and mutations, not entry

`SysOpen` and `SysFlock` require an idle local thread but no longer require
`TableReady` (`base.tla:97,165`). File creation precedes the insertion guard in
`syscall/open.rs:34-56`. Flock enters before lookup in `syscall/flock.rs:12-16`.
`TableReady` now checks only `tableOwner = Nil`. It remains on `FileTableInsert`,
`SysDup`, `SysClose`, `GetFileFast`, and `GetFileFastBadFd`.

The borrowed path is represented by the separate domain assumption
`SharedTable \/ Cardinality(Threads) = 1`, following the unshared table branch
in `fs/file/file_table.rs:355-360`. Each modeled fixture has one table. Its
borrowed variant therefore has one participating thread, instead of treating
an unavailable shared-table guard as an entry barrier. Every shipped MC cfg
still uses `SharedTable = TRUE` and retains its original thread domain.
The R2 fixtures cover both shared entry overlap and a single-thread borrow.

## R3: Search for a complete witness

`TraceNoWitness == ~TraceFullyConsumed` is a search invariant. Its violation
is the complete matching serialization. Exhaustive TLC completion without
that violation means that no serialization consumes the trace. A dead-end
candidate can no longer invalidate another candidate's complete witness.
`CallBase` still invokes all full guards. `ValidatePostState` still requires
exact record equality. There are no silent kernel actions or state filters.

The installed method was read before selecting this mechanism:

- `/home/chin39/.codex/plugins/cache/specula/specula-codex/1.2.0/skills/validation-workflow/guide.md` delegates trace validation to the trace workflow.
- The sibling `tla-trace-workflow/guide.md` and `references/validation.md` specify Phase 3's `success`, `trace_mismatch` and `error` statuses. The Category B section requires acceptance of one complete interleaving.
- `spec_generation/references/trace-spec-pattern.md` explains timebox branching, exact checks and the exclusion of liveness properties for Category B.
- The installed `tools/trace_debugger/src/tla_mcp/handlers/trace_validation.py:146-160` treats raw TLC no-error output as success. That parser cannot be applied directly to an inverted witness invariant.

`generation-checks/validate_trace.py` performs the conversion automatically:
TLC exit 12 with only `TraceNoWitness` violated becomes `success`/exit 0.
An exhaustive no-error TLC exit 0 becomes `trace_mismatch`/exit 1. Any other
invariant or execution error becomes `error`/exit 2. A timeout is INCOMPLETE.
Phase 3 must call this adapter. The exact command and raw outcome contract
are included in both `Trace.cfg` and `instrumentation-spec.md`.

The R3 fixture gives both EX-NB acquisitions overlapping intervals. The
A-first order consumes every event. The B-first acquisition matches locally
but leaves B holding an empty list, with neither A's acquisition nor B's
recorded conflict able to proceed. The fixture is accepted. A companion trace
forcing that losing order is rejected.

An execution prerequisite discovered while implementing R3/C7 also needed
correction: JSON string identities could not be compared with `Nil = 0` by
the supplied TLC. The first attempt failed in the original domain assumption.
The documented schema and synthetic generator now use positive integer
identities, while the JSON `traces` keys remain decimal strings. Trace loading
uses `ToString(t)` for the object lookup and checks its exact raw key domain.
This is identity normalization only. It does not remove any guard, event or
post-state comparison. The initial evaluation-error log is preserved.

## R4–R6: Check the promised observations

C09 keeps its four existing safety invariants and no longer asserts
`FixtureCompletes`. A successful request's Drop can repeatedly drain a loser
that re-enqueues before the next empty check (`flock.rs:139-157` and
`ostd/src/sync/wait.rs:119-131`). Weak fairness gives both threads execution
without ensuring that the winner returns and issues its planned unlock.
FL-CR-1 remains an open review-only scheduling question. No new scheduling
assumption, queue bound, retry bound or drain bound was introduced.

`ControlResults` (`MC.tla:284`) asserts each flock return before its observation
can be overwritten. In C01, A/B SH succeed, C's first EX-NB fails with EAGAIN,
and C's post-release EX-NB succeeds. C02's repeated same-owner EX, both UN
operations, independent probe and cleanup succeed. In C03, B's first probe
returns EAGAIN while A's alias remains, and its second probe succeeds after
final release. All other flock returns in these controls must succeed.

C10 adds C's open and EX-NB probe on T3 after T2's second operation, B's flock
syscall, actually returns (`MC.tla:130-138`). That boundary follows B's final
call-reference put and destruction. C reuses the now-free FD 2. `ControlResults`
requires its success. `MaxOpen` changes from 2 to 3 and `MaxFlock` from 3 to 4
only in `MC_hunt_4_inflight_close.cfg`. All other admission bounds are unchanged.

All ten brief section 5 obligations retain enabled hunts. General safety keeps
thread symmetry. Named-role and temporal hunts still omit it. Counters remain
in the fingerprint, and no production reaction is admission-bounded.
`CHECK_DEADLOCK FALSE` remains in every configuration. For trace replay this
allows candidate dead ends to coexist with a complete witness. MC continues
to use its named safety and temporal obligations for diagnosis.
