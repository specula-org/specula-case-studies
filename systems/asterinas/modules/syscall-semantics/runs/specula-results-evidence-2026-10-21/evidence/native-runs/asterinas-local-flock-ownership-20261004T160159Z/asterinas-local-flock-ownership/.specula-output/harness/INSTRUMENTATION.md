# Adjusting the local flock trace harness

This harness instruments Asterinas at `0c60537098f4c2949ad2d382aaf499de72263d76` for the Phase 3 agent. Read `STATUS.md` before using any result. A generated patch and a successful script parse do not establish a kernel execution or a matching trace.

Run `bash harness/run.sh` from `.specula-output/` under the campaign controller's existing heavy-stage allocation. The script verifies the exact reviewed harness hashes, copies its fixed spec companions into the private container, applies the patch, builds in the private Docker container, executes Linux controls and Asterinas fixtures, collects per-thread traces, and invokes the supplied witness-search adapter. It observes the 10 GiB build and 6 GiB TLC memory admission thresholds. The container is restricted to two CPUs, 8 GiB and 512 PIDs and receives only `/dev/kvm`. The guest uses the image's OVMF firmware for its EFI-only GRUB image, requests two CPUs and 2 GiB, and enables the project's early serial console. The exported `smp` value comes from the running guest's `ostd::cpu::num_cpus()`.

`apply.sh` accepts only the pinned baseline or the exact already-applied patch. It does not reset unrelated source changes. `clean.sh` reverses only the exact patch after checking that it can be reversed. `patches/instrumentation.patch` is the canonical source change, including the OSTD module copied from `src/flock_trace.rs`. Keep those copies equal. `src/patch_alloc.py` modifies only the private container's installed, hash-checked Rust source. It saves a scalar OFD token before each primitive, preserves the clone fetch-add, put fetch-sub and upgrade CAS, and passes the token with the actual outcome to OSTD. A delayed nonfinal put can therefore still be recorded after another task completes final destruction. The host Rust installation is unchanged.

## Capture points

The syscall hooks are in `kernel/core/src/syscall/{open,dup,close,flock}.rs`. Open records the new allocation, cloned table reference and original put separately. Close records FD removal while the original guard is held, then brackets its release. Wrapper functions observe return only after the original locals and synchronous destructors have dropped. `get_file_fast!` remains the real borrowed/shared-table lookup.

`kernel/core/src/fs/file/flock.rs` records list attempts, successful guards, conflict owners, registration, replacement, append/install, and retain decisions. It preserves the original Mutex and temporary Arc drop inside the retain closure. The FD identity map is published under the original insertion guard. Replacement saves only a local index/token before assignment and emits its event inside the actual old-item Drop. The scan's protected scalar copy follows observed removals because Rust's `Vec::retain` cannot expose a safe whole-list reference from inside the item's destructor. It is not reconstructed by running the TLA+ model. `inode_handle.rs` records the real payload destructor entry. The actual alloc `drop_in_place` return supplies its completion.

`ostd/src/sync/wait.rs` copies queue entries under the production spinlock. The waiter identity follows the actual request token. Wait and wake packets retain the actual swap outcomes. Closure has a trace-only marker set before the real close swap, inside that operation's timebox. An accepted wake records `closed=false` because it observed an unnotified live waiter. No owner reference is cloned for logging.

`ostd/src/task/scheduler/mod.rs` records the notification check under the existing runqueue guard. `kernel/core/src/sched/sched_class/mod.rs` records the guard release after dequeue or abort and the actual enqueue/recheck on wake. The park release interval starts before the operation and ends after the guard release. Internal list-Mutex waiters have no flock token and do not become flock queue events.

`ostd/src/flock_trace.rs` holds the per-task local projection, preallocated immutable event slots, scalar identity registry and exporter. Only the owning task mutates its local record. Short local interrupt exclusion protects the writer from reentry. No shared logger lock, per-event global sequence counter, formatting, allocation or owner Arc clone occurs in emission. Export uses a fixture-only `prctl(0x53504543, ...)` bridge after the relevant boundaries. Scalar active-address lookup retires after actual payload cleanup. Historical mappings remain available for the evidence export.

See `sites.tsv` for file and line locations after application. Arc/Weak primitive locations are also retained in `evidence/alloc-original.rs` and `alloc-instrumented.rs` once that setup has actually executed.

## Changing a field or boundary

Add a scalar or bounded protected copy to `Packet`, capture it at the real operation, and update `read_event` to serialize it. Control labels and continuations belong to `Local`. Do not use `Local` to predict a shared reference count, ownership, queue outcome or syscall return. `Trace.tla` compares the exact complete post-state record, so a new serialized state field also requires a reviewed matching check. There are no optional checks or silent state-changing actions.

To move a boundary, change the real source hook and bracket the operation with `stamp()` and `emit()`. Keep release operations inside their intervals. Preserve atomic return values instead of rereading mutable state. Keep the existing production guard while copying an aggregate. A new event requires a real hook, local continuation update if applicable, serialization, and an independently reviewed base/Trace mapping. Never add an event in the collector to complete a history.

After editing source, regenerate the tracked-file patch with `git diff --binary` and append the new OSTD module's `/dev/null` patch without staging or committing it. Update `src/flock_trace.rs` to those exact bytes. Preserve the old and proposed versions, diff, reason, triggering evidence and SHA-256 hashes. Obtain independent exact-version review under `resources.json.corrective_review_gate` before an affected build, guest or trace rerun. Record the reviewer and material dispositions. `evidence/runtime-reviewed.sha256` must describe the approved bytes, not an author's self-approval. Keep an unresolved gate incomplete and return it to the controller.

## Fixtures and evidence

`src/scenarios.c` uses the repository's regression `test.h` and invokes real open, dup, close and flock syscalls on one existing ordinary file. Worker threads exist before the traced opens, so these cases use the real shared-table reference path. The borrowed-table branch is not covered by these fixtures. Linux controls use the same binary on a separate tmpfs and record the actual host kernel and filesystem. They are controls against the fixed source oracle, not execution of the archived Linux v6.16.5 source.

C00 is a four-event open/table-guard overlap prefix. It assigns roles from observed `SYS_getcpu` values before trace registration and rejects unsuitable placement. C13 closes a descriptor while its original open Arc is still pending, then finishes both opens. These fixtures are not counted as executed until `STATUS.md` records their run.

C01-C05 cover shared ownership, aliases, final close, conversion and the failed-conversion oracle. C04 also has a parked SH waiter during downgrade. C06 preserves a prefix after both real conversions park. C07 separates release before admission, release after actual parking, and a notification between the wait swap and park check. C08 waits for a fresh second park after releasing the first blocker. C09 admits either winner. C10 closes the FD after the syscall parks. C11 delays only the actual successful temporary Weak upgrade until the other thread closes its FD, then preserves a prefix if the real destructor attempts the self-held Mutex. C12 supplies alias and close-before/after controls. The gate adds no owner reference and does not release the target Mutex.

The collector retains serial output, immutable raw per-thread NDJSON, identity maps, syscall returns, buffer/drop counts and original timestamps. It compresses all timestamps through one monotone mapping, preserves each thread's sequence and exports one NDJSON object containing the per-thread arrays. It does not sort concurrent events into one execution or reconstruct state from the model. A prefix is labelled separately from a completed case. Missing export, dropped records or a fixture failure cannot become a phase pass.

The coverage report names every missing event and computes genuine cross-thread overlaps, including the guide's 20 percent quality threshold. An accepted trace witness means that every supplied event matches the full base actions and exact captured post-state. It does not mean that a pending syscall returned or that a watchdog proved deadlock. Use `spec/generation-checks/validate_trace.py`, since this campaign's `TraceNoWitness` invariant has the reviewed existential acceptance convention. Do not feed its raw exit code to the generic success parser.
