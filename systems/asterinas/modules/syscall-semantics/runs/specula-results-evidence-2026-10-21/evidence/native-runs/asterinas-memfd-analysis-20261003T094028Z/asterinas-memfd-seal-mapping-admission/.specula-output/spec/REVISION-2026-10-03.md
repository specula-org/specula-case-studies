# Memfd suite revision, 2026-10-03

The review findings P1 and P2 in `spec/review-specgen.md` were the only input to this revision. The approved brief, analysis, pinned source and review diagnostics were used as read-only references for those fixes. The source remains at `0c60537098f4c2949ad2d382aaf499de72263d76`. No kernel change, invariant change or unrelated modeling change was made. Changes remain uncommitted in the working tree.

## P1: Match cursor skipping and source events

`CursorUnmap` (`base.tla:370`) and `CursorProtect` (`base.tla:382`) now select the lowest remaining address with an existing PTE. Absent entries are skipped inside the action, just as the source cursor skips them inside its call. Only a returned mapped page adds to `touched`. When none remains, the action moves directly to cursor completion and then the existing dispatch/sync steps. Protect still writes the requested permissions without hardware WRITE, including when this leaves the flags unchanged.

The source boundaries are `take_next` at `ostd/src/mm/page_table/cursor/mod.rs:484-522` and `protect_next` at `ostd/src/mm/page_table/cursor/mod.rs:525-564`. The unmap caller finishes on `None` at `ostd/src/mm/vm_space.rs:475-482`, and protection finishes on `None` or range end at `kernel/core/src/vm/vmar/vm_mapping.rs:865-871`. The three-page, ordinary-page abstraction retains one returned entry per step. Page-table hierarchy and huge-page fragments remain outside the approved model.

The corresponding `TraceCursorUnmap` and `TraceCursorProtect` wrappers (`Trace.tla:206,212`) still call the complete base actions and now also validate the source operation's returned `range`. A mapped entry returns `[lo,hi]`. Cursor completion returns `[]`. This distinguishes an unchanged flag update from completion. The instrumentation rows (`instrumentation-spec.md:94-95`) specify the same boundaries, skip behavior and payload. There are still 32 base actions, 32 wrappers and 32 event rows. Exact `ValidatePostState` equality, replay completion checks and the absence of silent actions are preserved.

The review-derived source-empty-unmap fixture retains its 31-event sequence. Its historical shadow `touched` and flush lists included three skipped pages, so regeneration corrects those lists to empty and adds `range=[]` to the completion event. It has an unfaulted three-page mapping, zero PTE removals and one cursor completion. Both ordinary replay and the complete-path search accept it. The search's `TraceNotComplete` witness ends at `l=32`. The corrupted seal snapshot is still rejected by `TraceMatched` at `l=2`.

## P2: Complete scenario 1's protocol search

`MC_hunt_scenario1_protocol.cfg` uses the existing `Scenario="scenario1"` selection, so it explores exactly the same `AdmissionPlans`. It enables `SealPublicationAndFreeze` and `RetainedWriteEligibility`, matching the reviewer's protocol-only reference. The original scenario-1 hunt and the separate TV-1a, TV-1b and TV-2 configurations retain all their compatibility predicates. No existing enablement was weakened.

The new protocol configuration completed 1,674 distinct states to depth 58 with zero queued states, no enabled invariant violation and no deadlock. Its smaller state count than the review's 1,712-state diagnostic comes from P1 removing absent-page steps. The original scenario-1 compatibility hunt still stops at depth 14 with 37 queued states and is not counted as completed protocol coverage.

Thread symmetry, the finite request drivers, the two-thread/three-page/six-owner bounds, all invariants and every brief §5 property remain unchanged. The only enablement change is adding the protocol-only configuration. All ten MC configurations were rerun. The six standard/protocol runs completed, and the four compatibility configurations retained their expected named counterexamples. All ten synthetic trace checks met their expected outcomes. These are bounded model and synthetic replay results. Kernel execution, Linux differential tests and genuine implementation-trace correspondence remain **NOT_RUN**.
