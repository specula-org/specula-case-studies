## Representation and action changes

P1 replaces heterogeneous value domains. Durations are records with a boolean
`timed` field and natural-number `ticks`. `Never`, `After(0)` and `After(1)`
preserve the original three inputs. Every lock and entry owner is a two-element
string/integer tuple, including `<<"none",0>>` and `<<"local",0>>`. Optional
wait/call IDs use integer zero, with positive generation domains. A call's
optional controller is an empty or singleton sequence, preserving controller
symmetry without choosing a distinguished actor. Result enums still use the
string `"none"` because their other values are strings. The v2 trace schema
uses matching JSON objects, arrays and integer sentinels.

All configurations retain their original invariant lists, workload constants,
bounds, controller symmetry, budget-preserving view, capacity constraint and
`CHECK_DEADLOCK FALSE`. The duration constant now uses an operator override.
The base environment advances in integer unit steps instead of enumerating
`Nat` as an action parameter. Arbitrarily large advances remain reachable by
successive steps, with no bound on time. This makes base successor evaluation
executable by TLC. `MCClock` extends its finite clock quotient to a sampled deadline awaiting
publication, so even the first timer can age between its local read and heap
insertion. No admission bound changes. Untimed configurations cannot reach
this additional clock branch.

P2a adds `TimerSetClock(g,t)` and `PauseTimeoutClock(g,t)`. They save a local
sample before `TimerSetTimeout` or `PauseTimeoutRemain` consumes it. The
`armRead` and `remainRead` PCs expose those boundaries. `Live` and `Enrolled`
include the new pre-publication PC so the split does not drop an existing
eligible waiter. Deadline calculation follows `timer.rs:67-68`. Remaining-time
comparison follows `timer.rs:106-109`. Consumers leave global time unchanged.
`ClockAdvance` can record another CPU's later clock observation without
modifying either local sample.

`TimerCollectClock(t)` begins a collection batch with one saved sample.
`TimerCollect` uses that sample for every expiry decision. `TimerCollectEnd`
ends the batch without refreshing it. Collected callbacks become runnable
only at that heap-release boundary (`timer.rs:217-221`). The end condition
follows the loop's first future heap entry at lines 207-215. It does not require
pruning cancelled nodes beyond that entry before the source would revisit them. This follows `timer.rs:200-218`, in
particular the single `current_time` read at line 206 and comparison at line
211. Timer publication observes the heap lock at `timer.rs:188-192`. This
source-backed exclusion is needed by the new batch interval, not added in
response to an invariant failure. Collection remains reactive and unbounded.
The fair configuration extends its existing service assumption to the new
collection boundaries.

Trace replay binds operation reads to generation `g`. Collection reads bind
to the pair `(pid, batch)`, where `batch` is the read event's per-stream sequence
number. Every pop and batch end checks that same pair. The base model reuses
one batch slot. Replay keeps the trace identity separately so finite admission
does not impose a bound on the number of collection attempts. Read and
consumer post-states include the saved sample. No kernel event is silent.

P2b adds `WaiterSpuriousReturn(g)` from `sleep` to `wait`, following
`ostd/src/task/scheduler/mod.rs:441-444` and `ostd/src/sync/wait.rs:272-275`.
It changes only the waiter PC. The next `WakerDoWait` must still perform its
atomic swap. The action cannot accept a notification, increment a wake or
return count, or manufacture completion. The trace wrapper and instrumentation
row record the scheduler boundary explicitly.

Saved-original-bucket cleanup at `futex.rs:124` and both migration helpers'
counting at `futex.rs:500-533` are preserved. All eight brief properties remain
enabled across the original configurations. TV-1 through TV-3 still have
separate checks, and resource accounting cannot stop the later live-migration
configuration before its own oracle is reached.

## Counterexample interpretation

The quota counterexamples use indefinite waits and preserve their enrollment
and lock order. They do not depend on timer samples or a spurious park return.
`generation-checks/quota-evidence.json` records each violated property, trace
length and final call state, extracted with the Specula TLC summary/state tools.

- `MC_hunt_s2_quotas` and `MC_hunt_s2_zero_wake` reach one accepted wake with
  raw wake quota zero. This follows the unchanged conversion at
  `syscall/futex.rs:105-109,146-150` and accepted-count update at
  `posix_thread/futex.rs:488-495`.
- `MC_hunt_s2_zero_move_same_bucket` reaches one move with raw migration quota
  zero. The source changes the matching key and increments the count before
  testing the quota at `posix_thread/futex.rs:502-508`.
- `MC_hunt_s2_return_count` records one wake and one cross-bucket move, then
  returns one. The extraction and append follow `posix_thread/futex.rs:520-533`,
  and the return is `Ok(nwakes)` at line 381.
- `MC_hunt_s2_same_address` returns one for two eligible waits and quotas
  `(1,1)`. The source takes the WAKE shortcut at `posix_thread/futex.rs:353-354`.
  The additional processed count remains the existing Linux oracle, not a
  physical move or an implementation change.

These are source-backed model candidates. Kernel execution and Linux controls
remain unrun. No representation artifact was found in these quota histories, and
no invariant or implementation action was changed to hide them.

The first P2a batch implementation let callbacks run before `TimerCollectEnd`.
The initial owner and live-migration witnesses exposed that ordering artifact:
the collection was still active after its own callback had executed. The source
releases the heap guard before invoking callbacks (`timer.rs:217-221`). The
revision now retains a `collected` phase and the batch's `ready` vector until
`TimerCollectEnd` makes those callbacks `due`. Its mandatory post-state also
checks all released callback states. The affected timed checks are rerun and
the earlier logs are retained as superseded evidence. The untimed checks cannot
enter a collection batch, so their reachable graphs are unchanged by this
constant-state extension. No ownership or compatibility oracle was weakened.

The corrected `ResourceAccountingBalance` witness has 56 states. Generation 2
is registered at A, arms deadline 1, and is collected at sample 1. State 21
releases the collection batch before its callback begins. It consumes the
timer notification and reaches original-bucket cleanup after reading time 1.
The first requeue takes both bucket locks before that cleanup, wakes generation
1 and transfers generation 2 to B. Generation 2 then misses in original bucket
A, returns success and closes. At state 56 the controller has returned, both
bucket locks and all callback references have drained, yet bucket B still owns
the completed generation. This follows `futex.rs:114-139,366-381,477-482,520-533`
and `timer.rs:206-221`. Success itself is not the violation. The retained owner
is. The matching same-bucket control completes without a violation.

The corrected `LiveMigrationExhaustion` witness has 93 states. Its initial
collection likewise ends before callback execution. After both old waits have
returned, fresh generations 3 and 4 join B behind retained closed generation 2.
The second requeue snapshots cohort `{3,4}` at state 80. It rejects the closed
waker at states 81-82 (`wait.rs:262-265`, `futex.rs:488-495`), wakes and removes
generation 3, then spends migration quota one on generation 2 at states 88-90
(`futex.rs:520-533`). Generation 4 remains at B, and state 93 sets the existing
exhaustion observer. No timer, close or independent notification interferes
with that fresh cohort. `generation-checks/ownership-evidence.json` records
all state changes for both histories. These final witnesses follow the pinned
implementation and do not rely on a representation artifact.

## Reproduction

From the workspace root, run `python3 spec/generation-checks/audit_suite.py`
and `python3 spec/generation-checks/generate_traces.py`. The latter deterministically
writes a 76-event synthetic attempt and a copy changing the selected WAIT ID
and its matching `ready` entry in the first `TimerCollect` event. The valid
attempt includes a spurious park return, deadline publication delayed across a newer global clock record, and
a collection sampled at 1 that executes after the global observation of 2.
The corrupted event attempts to collect deadline 2 using that saved sample 1.
All declared waits and the controller call finish in the valid attempt.

`python3 spec/generation-checks/run_checks.py mc` runs the 16 original MC
configurations sequentially. `base` requests 20 reproducible, depth-100
simulations per worker with `base.cfg`. The two workers produced 40 traces
and checked 4,001 states. `trace` replays both generated fixtures using
`Trace.cfg` and
the `JSON` environment override. Existing log files are retained. The runner
skips already logged MC configurations and refuses to overwrite other logs.
Use a fresh copy or archive earlier logs to repeat a run. Every result records
the exact Java command, exit status, duration and available exploration counts.

`python3 spec/generation-checks/run_checks.py types` additionally evaluates
initialization and three-step simulations against the final source for all
16 MC configurations. The 11 untimed configurations never enter a timer
batch. Their earlier full searches are still applicable:
`TimedBound=0` makes the changed timer branches unreachable, and `ready=<<>>`
is a constant extension of each reachable state. The additional short runs
check the final record shape and are C1 probes, not replacements for the C5
searches. They use the original configurations without editing any bound.
The final base simulation and synthetic replays are also repeated after the
heap-head exit refinement. The three focused timed searches admit at most one
timer, for which the old and refined exit predicates are equivalent.

The broad `MC.cfg` run loaded the earlier batch-end predicate before the final
heap-head refinement. Its reported depth was 6. Reaching two pending timers
requires at least 18 primitive steps, so the refined branch cannot affect its
explored prefix. That incomplete prefix is retained as such. The fairness
configuration and the final type/replay checks load the final suite. No result
claims coverage of the unexplored deeper states.

Each TLC process uses the supplied Java and jars, `-Xmx2g`, two workers and
`timeout 1200`. Metadata is under `states/`. No reduced-bound configuration is
substituted for an original. The base simulations establish reachable-step
evaluation in the intentionally unbounded base environment, not exhaustion.
`TraceIncomplete` is the existing deliberate reachability sentinel. Only its
violation after all cursors finish and every other invariant holds is an
accepted replay witness. A corrupted attempt must exhaust all reachable
prefixes without that witness before it is called rejected.
