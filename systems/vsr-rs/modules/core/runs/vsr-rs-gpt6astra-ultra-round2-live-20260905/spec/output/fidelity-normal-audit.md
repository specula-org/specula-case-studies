## Invariant meaning and limits

`CommittedPrefixAgreement` compares retained full-request observations at each index across replicas, time, and crashes (`base.tla:375-390,487-488`). `AppliedPrefix` compares the execution observer against the current, potentially replaced log (`490-492`), so log-install prefix corruption is not assumed away. `AtMostOnce` is per application incarnation, and `ReplyCorrect` checks emitted replies against historical committed identity/results (`493-499`), consistent with the modeling brief. The retained real traces contain commits and replies, so their safety checks do not exercise only empty histories.

`DurableViewConsistent` is bookkeeping enforced by the conforming publication wrapper (`388,517`); it is not a filesystem durability check. Accumulator arithmetic is the selected application specialization, not validation of arbitrary application implementations. `MC.tla:67-73` explicitly leaves client progress disabled because finite callback budgets and arbitrary network loss supply no stabilization/fair-delivery witness.

Trace coverage is limited to memberships 3 and 4, views 0 and 1, one `OnDoViewChange`, two `OnStartView`, and two `OnStartViewChange` events. Recovery occurs only for replica 1 in view 0, using fresh raw nonces 101 and 202 (`harness/src/scenarios.rs:219-252`). These traces provide no combined recovery/view-change, repeated escalation, or membership-2 evidence. Event-type coverage is not branch or behavior completeness.

The owner explicitly assumes `N >= 2`, successful persistence outside replica destruction, and one outstanding client request (`harness/src/owner.rs:32,96-100,146-151`). The independent EX-START, LIB-SINGLE, EX-WRITER, EX-FSYNC, EX-NONCE, and AS-* handoffs remain outside these traces (`harness/INSTRUMENTATION.md:85-89`). This audit neither resolves those candidates nor counts them as protocol findings.
