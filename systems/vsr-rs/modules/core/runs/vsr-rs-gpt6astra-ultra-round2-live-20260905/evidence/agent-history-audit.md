## Retained Lean assurance scope

1. **Proved narrow model properties, full theorem open.** Exact `sorry` search returns only `lean/Vsr/Safety.lean:205` (`NoPanic ∧ PrefixAgreement ∧ Durability`) and `lean/Vsr/Liveness.lean:93` (general `settles`). `Safety.lean:184-195` proves sent WF and bounded commit through local invariant. These preserve numerical well-formedness even when totalized handlers set panicked; they do not establish no panic. README `27-50,66-120,166-192` accurately distinguishes these major gaps. `Inv.init`, `Inv.prefixAgreement`, selected GetState/catch-up/commit helper preservation are present; no whole-transition Inv preservation proof is claimed. Quorum.lean `15-51` requires distinct in-range members and proves intersection, not the protocol endgame.

2. **Differential testing, not verified translation.** `verify/verify_tests.rs:10-11,88-119` defaults to 40 seeds x 200 steps and skips successfully if lake is absent (`90-93`). Generator selects only 3 and 5 replicas, primary timeout 2, two clients, 60% delivery, 15% idle, requests or rare recoveries (`verify/lib.rs:340-397`). It limits clients to one outstanding request (`369-385`) and uses increasing nonces (`388-392`). The Rust replay drains after each delivered message, idle, request or recover (`112-165`); observable state and every output are compared after each step (`167-190,289-308`). Private acknowledgment/client tables and timer fields are not directly compared (README `228-244`): disagreement matters only if a sampled continuation exposes it. No example socket/filesystem/clock behavior participates.

3. **Recovery assumes perfect persisted view in the model.** `System.lean:30-32,72-73` always recovers from the current in-memory view, effectively making persistence atomic and infallible. No read/parse fallback, dropped rename, failed fsync, or release-before-persist step exists. Therefore it cannot discharge the kvstore startup or directory-durability questions.

4. **Nonce obligation mismatch in abstract reachability.** `lib.rs:505-510` demands a nonce distinct from every prior recovery for that replica. `System.lean:32,72-73` permits any Nat, without a fresh-nonce side condition or nonce-history set. The generator does keep nonces fresh (`verify/lib.rs:388-392`), and retained paper handlers explicitly say fresh (`docs/paper/main.tex:1223-1224,1424-1429`). This is a statement/coverage boundary to repair when completing proofs, **not a bug in a caller-conforming library and not a full counterexample claimed here**. Future TLA+ base model must encode freshness; a separate example clock candidate can intentionally explore the example's failure to guarantee it.

5. **Singleton omitted, and `settles` is weaker than request progress.** Combined invariant is for >=2 replicas (README `79-84`; proof/model.md `24`; paper `308-319`). `Sync.settled` (`Liveness.lean:63-69`) checks queue empty and every replica Normal at same view; it does not require pending requests answered, logs committed, or state-machine convergence. A one-member normal primary appends an operation without emitting a peer message (`lib.rs:677-694,1404-1409`), so the model can be settled even while the request has no commit/reply. This directly explains why the retained liveness theorem/regression cannot discharge the singleton contract/progress question. Keep the singleton mechanism as its own test/API candidate.

6. **Bounded liveness has concrete scheduler assumptions.** `Liveness.lean:50-58` idles all replicas, delivers queue plus all idle outputs, delays delivery-generated outputs one round; `78` discards old messages when entering this synchronous convergence experiment. `Check.lean:308-315` uses 1000 rounds and returns true immediately when there is no non-recovering quorum. `Storm` theorems `128-143` prove one scenario settles by round 8/view 3 and is settled at round 30; they do not prove arbitrary finite/infinite liveness or real sender isolation. Code-review candidates must not be pruned merely because a finite settles check passed.

7. **Intentional mathematical abstraction.** Types.lean `8-13` uses Nat for Rust usize identities and counters, Replica.lean `43-50` Nat for u32 attempts and u64 nonce. Config primaryId (`Types.lean:24`) is total Nat modulo, unlike empty Rust Config's indexing/modulo panic (`lib.rs:86-87`). Model panic flags make functions total and may continue after an assertion (`Replica.lean:144-177,222-235`), unlike Rust aborting that step. These are constraints on the conformance scope, not automatically protocol defects; neither realistic integer-overflow triggers nor malformed-message library violations are established here.

8. **Veil and hand notes are separate evidence.** `proof/README.md:12-14,55-62` explicitly identifies model subject and incomplete hand proof. `veil/README.md:22-46` describes an abstraction with axiomatized quorum intersection, nondeterministic timers, unioned log fragments, and dropped clients/replies/state machine. It explicitly says nothing directly follows about lib.rs. Retained build/run artifacts are historical experiments, not a successful current exhaustive verification. No retained log or theorem completion is promoted to a production correctness guarantee.

## Live protocol reading and exclusions

The full library read found no independently verified new conforming-library safety defect beyond candidates handled by the parent. Message-shape assertions and missing sender authentication are only triggerable via forged/malformed/misrouted messages absent a caller/transport mechanism, not via arbitrary invented Byzantine input in this crash-fault analysis. `on_get_state` may answer on any normal replica (`lib.rs:818-838`), but conforming `send_get_state` routes to the primary (`1390-1397`); normal-path missing is_primary check is not enough for a new finding. The same-view-state, delayed acknowledgment and recovery paths have compensating view/status/freshness guards listed above. API singleton progress remains a direct finite test candidate; full protocol model-checking should be reserved for genuinely open interleavings, not erased current guards or restated historical fixes.
