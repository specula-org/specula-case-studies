## Property scope and modeling limits

- Full position-indexed logs and application execution history are retained. `CommittedPrefixAgreement` compares all past executions and original invocations, and verifies that installation did not rewrite a replica's executed prefix. `CommittedHistorySurvives` remembers violations at history installation: overlapping commitments from no newer view must agree; a fresh DVC selection must include earlier-view commitments already observed before selection. A delayed old-view snapshot may lag or retain an uncommitted suffix that a newer view replaced. There is **no** requirement for all replicas to have a globally fresh log, or for every committed entry to have a quorum of live copies at every instant.
- This installation observer plus subsequent commits/reads targets erasure. It is not a full independent proof that every historical operation can always be recovered from all combinations of buffers and replicas. A lost suffix that is never selected, executed, or observed again may require a continuation to reveal harm. The three-call workload permits that continuation; absence of a witness is not proof.
- `ClientLinearizability` enumerates distinct sequential histories of original invocations, optionally including outstanding operations, and checks completed results and every completion-before-invocation edge. Concurrent requests have no imposed order. `NoDuplicateExecution` concerns logical log occurrences, allowing recovery replay of lost application state.
- Stable timing is explicit: each healthy replica ticks once per round in arbitrary order, and all healthy message/owner work drains between timer/retry/new-request events, with fair handlers, outputs, client observation and recurring timer opportunities. This is a strong synchronous subcase. Arbitrary eventual delivery alone and delays exceeding capped backoff are not covered. No primary is assumed to be normal in the liveness conclusion.
- Stable work is a bounded stream of 3 invocations with at most 1 admitted in the fault prefix, so at least 2 are newly invoked after stabilization; later calls can follow earlier responses. This is stronger than only draining the fault-prefix requests but is **not** an infinite sustained-work theorem. `BoundedNewWorkIsAdmitted` prevents a pass caused by never admitting configured work. Search-bound alarms must be resolved before interpreting any temporal result.
- Numeric replica identities cannot be permuted independently because of modulo primary selection, initial primary 0 and DVC tie order. Safety hunts permute only client model values; liveness uses no symmetry. The state view keeps fault counters: excluding them would merge different remaining budgets unsoundly.
- Equal network envelopes are coalesced in a set. A bounded duplicate-delivery action keeps the same envelope while running the full handler; different response snapshots remain distinct. Ordered per-owner outputs and all distinct full log/reply contents are retained. Trace normalization uses the same set projection and must flag repeated delivery with `keep=true` until the last equal envelope is consumed.
- Timers keep actual waiting and capped backoff. Only stable-period counts at/above PrimaryTimeout and attempt counts at/above 10 are saturated, a projection preserving all guards in lib.rs:1291-1305. No old backoff fix is reverted.
- One key suffices for the proposed Put/Get order and framing mechanisms; no multi-key transaction claim. Fresh nonces, authentic identities/content, deterministic execution and correctly durable views are core caller assumptions. One pending request per client is an explicit workload restriction; this generation does not establish that arbitrary pipelining violates a documented library contract.

## Brief §6.2/§6.3 and exclusions

TV-1 is an existing **integration** finding in the supplied evidence, not a new result of this generation. The refinement represents only its witnessed nonempty ASCII final-value prefix. Confirm bytes with `../evidence/frame-regression/{expected.frame,received.frame,append.rs}` and the independent three-binary result. Ordinary fragmentation completes unchanged; a read-error path drops the partial input. TV-2 forwarded replies and TV-3 log-carrying frame variants are intentionally not independently abstracted or counted as additional bugs; they require their stated executable continuations.

N=2 recovery availability (CR-1) remains contract review, not a within-budget crash hunt: quorum 2 and FailureBudget 0 cannot support a recovery after an allowed failure. CR-2 caller obligations and CR-3 capped timing assumptions are preserved. Singleton acceptance, unreadable view-file fallback, directory fsync, nonce freshness, shared FIFO sender blocking, issue #9 / PR #10 reconnect/disconnect/client-ID mechanisms, and generic observer gaps are excluded as requested.
