The important historical mechanisms are:

- **Task identity must be created in the shared start transition.** `9002e943b069f941a6fc92e3a6058117dfdd6c8b` moves StartedClock assignment from the ordinary start API into AddActivityTaskStartedEvent, and gives eager start the same clock before token creation. Eager cancellation previously could not reconstruct the original token completely. Current assignment remains at `service/history/workflow/mutable_state_impl.go:4499`. This is a fixed path inconsistency, suitable as reference context only.
- **Timeout reason and retry policy are separate observations.** `0ded458f739764eefe2b616285338eead7deb18e` fixes ScheduleToStart/Close RetryState from NON_RETRYABLE_FAILURE to TIMEOUT. Its removal of timeout-type conversion caused a regression corrected by `a5ea2aae30bc1b303c5a5b2724095d912f033a45`: an attempt timeout with insufficient time for another retry resolves with ScheduleToClose type; explicitly reported worker failure remains failed. Current conversion: `timer_queue_active_task_executor.go:315-323`; policy classification: `mutable_state_impl.go:6895-6909`. `8c64263019cb95213135d9d4b62b82313fa68fcd` previously corrected the associated failure message while retaining last heartbeat details. These are historical contract evidence, not novel targets.
- **A dispatched timer must remain actionable after wall-clock rollback.** `a5b3c01ff54453379d6660d77b13651fb42e0a22` bases expiry on max(now, task visibility) because persisted timestamps lose Go monotonic-clock metadata. It prevents a timer admitted to the scheduler from being dropped merely because the wall clock moved back before execution. The commit explicitly acknowledges it may run timer logic earlier than newly observed wall time. Do not propose a strict wall-clock guard that contradicts this intended compensation.
- **Dropping a corrupt delivery is deliberate.** `49761096f45ead015b39d4dcbe7a92ea54b36167` converts serialization/deserialization errors to DataLoss and drops Internal/DataLoss Activity/WFT deliveries instead of recycling them indefinitely. Matching current behavior is `matching_engine.go:1038-1045`. This changes the environment assumptions for progress: healthy recoverable persistence is distinct from corrupted history that is treated as a terminal delivery error. The core-filtered patch contained only a typo; the substantive full commit was inspected and preserved.
- **Retry delay override is not capped by the policy interval.** `7708a7c93de1f8acc4fb9bad0642a7c2cc2fde4b` honors explicit application next_retry_delay above MaximumInterval; deadlines/attempt limits still apply in the subsequent retry calculation. Current override is `mutable_state_impl.go:6942-6958`.
- **Observation timestamps must not be synthesized from start.** `c6fb6b8331599b2b43b6da424224b26cb9d46904` stops fabricating LastHeartbeatTime at Activity start while heartbeat timeout still falls back to started time. `a4e6f11954a3d60e7e7159cb28324a09d22fb923` captures metric inputs before retry clears start fields and maps nil timestamps to zero rather than epoch. These are fixed observation/metrics defects, not server durability violations.
- **Bookkeeping must follow the actual transition.** `691bd205b7a31b87fd22d38271da779ca3975aff` avoids decreasing approximate size when retry calculation rejects a retry. `3a1b707f39d24e122c43b00fcfc2b7c2502323fb`, `24a39ce1d21605967016f3dd2ca51dee343bc1c6`, and `7b98006bec699c3b41499f7d9e1ebac93c5494a2` refactor retry/start/timer updates into common mutation helpers and generate retry tasks from updated ActivityInfo. Refactors are infrastructure context, not extra bug counts.
- **Cache reload must not continue with partial invalid state.** `598aa479cf9962e8f1f33a58b42efc1a8e1c2edb` rejects a dirty transaction at StartTransaction; current guard is `mutable_state_impl.go:7574-7585`. `3e6602fb10af41d55dad0b05f501d9b06613726e` avoids a typed-nil interface during DB-load failure, but the commit explicitly says the nil return was not reachable then: record prospective hardening, not a confirmed historical crash. `182ae5a394499ce8763a8b6ff91107c8b28b3259` initializes execution state before legacy ExecutionTime backfill reads history. `8b1993b7e45148fbd7c1fe1241a75534b0b235f9` distinguishes Internal contract breaches from retryable Unavailable. These support careful error classification and cache eviction analysis; no new issue is claimed.
