# Bounded clock regions

The source allocation rule admits minimum scheduled times up to the observed clock plus the configured 1000 ms reader shift. The unreduced reference in `output/continuation-20260911/mc-full-clock/` enumerates every integer in that interval, subject to the monotonically retained floor. The convergence configuration and all original fault, attempt, request, Activity, message and time bounds remain unchanged.

The reduced wrapper uses an exact quotient for the bounded safety configurations, not a shorter timeout or a smaller reader-shift bound. Let H = 1 + TimeLimit. `MCTypeOK` checks `now = 1 + faults.Time`; therefore every reachable clock is at most H. Retain every floor at most H and one representative H+1 for the nonempty interval above H. The fingerprint view maps only physical task visibility and the remembered floor above H to H+1, including immutable pending write/task copies. Logical deadlines, timer masks, heartbeat watermarks, identities, versions, Activity state, ownership, receipts, request payloads and fault budgets stay exact.

Why the quotient preserves the checked safety properties and enabled protocol behavior:

- A physical task later than H never satisfies TaskReady. It cannot enter timeout/retry processing, acquire an acknowledgement, or be redelivered. HB watermark comparisons and timeout scans only evaluate tasks which pass that guard.
- A retirement batch containing any future scheduled task is disabled because that task cannot be ackable. Batches ending at a nonfuture key have exactly the same members. WFT/immediate-task keys are assigned the current clock and are not future scheduled cues.
- Allocation at a remembered floor above H produces only future scheduled visibility. Immediate tasks still receive the exact current clock. Monotonic floors cannot return to a nonfuture region; every future floor choice has the same enabled future-region successors. Physical visibility generated from a later logical deadline also remains in the future region. Logical deadlines are retained for earliest-cue generation and coverage comparisons.
- Task IDs are distinct on reachable states, so mapping visibility does not merge different task records. The active safety predicates do not compare two unread future physical times. Their time-sensitive work-coverage predicate uses the retained logical deadline. The view additionally omits only observed replies and raw History-append bookkeeping; neither enables protocol behavior (per-attempt append receipts remain exact).

This reduction applies to the bounded safety runs with the current action definitions. It is not a proof of unbounded progress. A progress run must allow time to reach physical cues beyond its initial horizon; the old finite-time progress configuration cannot justify that premise. The unreduced and reduced MC.cfg runs are retained separately with their complete commands, model hashes, statistics and completion status. Original generation-stage incomplete results are also retained.
