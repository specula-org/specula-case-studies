# temporal-activity model boundary

**Current validation:** 21/21 complete real replays and the completed bounded safety baseline pass. The generation-stage material below is historical; current evidence, coverage and limitations are in [validation-report.md](validation-report.md).

Category A (distributed/message-passing), determined before specification generation from brief section 1 and the pinned source. Skill phases run sequentially in one agent. Source revision verified clean: `0c010ce5fe8c0180aa7573c72fe8fc87c6df7025`.

The reference model covers one open Workflow Run with ordinary, non-eager Activities, honest issued tokens, bounded valid payloads, one active cluster and SQL execution/task atomicity. The intended trace backend is the analysis baseline's file-backed SQLite/WAL/synchronous=NORMAL. This phase does not establish power-loss durability or run a database/process restart. Dynamic configuration: retry-stamp increment is a constant (baseline false, alternate hunts true); worker-control cancellation false; eager execution explicitly declined; no pause/routing/namespace rules/time skipping. Pause/unpause, ResetActivity and ByID are deferred extensions with distinct contracts, as requested by the brief.

Activity IDs are ordered ranks of actual ScheduledEventIDs within this Run. Logical time uses integer milliseconds after a bootstrap origin later than year 2000; -1 denotes absent timestamps and 0 the reloaded heartbeat watermark. Source comparisons truncate timer times to milliseconds. The current namespace Version is constant; StartVersion retains its zero compatibility behavior. Retry policies use configured positive integer intervals/coefficient and finite attempts; arithmetic overflow, arbitrary application retry-delay overrides, and legacy records missing FirstScheduledTime are outside the initial configuration.

One Workflow lease keeps local handlers mutually exclusive. Their mutation, close-transaction generation, raw History append, atomic SQL execution/task write, persistence return, lease release, notifications and API delivery are distinct actions. A backend write may remain in flight after timeout; reacquiring RangeID fences it before reliable reload. Internal storage retry reuses the expected DB version, permitting a final condition error after an earlier successful commit. Raw History batches are not logical history. The DB version contract is the modern nonzero DBRecordVersion branch; legacy NextEventID CAS is documented but not exercised.

A physical ActivityTimeoutTask rescans all current logical deadlines, ordered by timestamp, ScheduledEventID and timeout type. The scan is a pure recursive in-lease computation, so all retries/terminals in one scan share one mutation. Post-scan timer generation and task acknowledgement remain separate. No stamp or receiver-attempt/not-before guard is invented. Task-copy identity is separate from its durable source task; ordinary worker tokens leave ActivityAttemptStamp at zero (matching_engine.go:3429-3447).

Workflow history is projected to ordered Activity events. WorkflowTask state, the terminal events visible at its accepted start, and consumption are explicit. ActivityInfo is deleted at terminal resolution. Intermediate retry-policy starts remain in ActivityInfo until terminal Started-event materialization. A preexisting buffer blocks Workflow close; command-generated immediate cancellation can be discarded on the same transaction's close. Client cancellation requests, heartbeat observation and cancellation acknowledgement are distinct.

Trace fidelity remains INCOMPLETE until the next phase supplies complete independently observed executions. Specification syntax checks and synthetic controls cannot establish Temporal fidelity. Run commands, bounds, logs and any completed TLC state counts are recorded separately in evidence and verification.md.

The final suite has 56 explicit transition boundaries. Rejected buffered Workflow close is represented through separate cache clear, reload, and WFT failure/renewal steps. Task retirement is one category/range-batch deletion; scheduled buckets retire together. Failure request heartbeat details distinguish nil (-1), present-empty (0), and the modeled nonempty checkpoint (1). WFT transport is an interface abstraction; Activity dispatch/poll acceptance and worker result transport are explicit.
