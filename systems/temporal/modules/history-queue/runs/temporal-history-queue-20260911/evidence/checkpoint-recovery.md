## New source-review finding CR1: a removed read-cursor element abandons later scopes

Discovery: parent source review of ReaderImpl.ShrinkSlices, independently confirmed by this agent's native queue plus file SQLite test. No model-checking discovery or reconfirmation occurred.

Mechanism: reader.go351-369 removes an empty list element without repairing nextReadSlice. An exact full batch can leave Slice.MoreTasks true because an iterator remains even though its minimum equals the scope maximum (iterator.go53-62; slice.go307-334,411-412). If its executables ACK before the next load, checkpoint ShrinkScope makes the first scope empty and removes that element. The next read consumes the orphan's exhausted iterator then advances through removedElement.Next(), yielding nil at reader.go480. A later nonempty scope stays in r.slices but is never selected. Reader.Notify372-383 only wakes; it does not reset the cursor. Default processNewRange modifies reader0 only. With maxReaders2, move-group action scans only reader0; no new loaded groups means no mutation to repair reader1.

Native reachability schedule in queue_base_recovery_sqlite_test.go158 onward:

1. Persist500 WorkflowTask rows plus ActivityTask502 into real SQLite through ExecutionManager.AddHistoryTasks. Start from default scopes[1,501),[501,503), high503. Schedule eight native load turns with batch100 and hold executable ACKs;501 tasks are pending.
2. Run real queue.checkpoint: base500 move-group action moves namespace to reader1 (log confirms counter501). ACK IDs1..400; checkpoint shrinks reader1 scopes to[401,501),[502,503), deletes prefix and persists QueueState. Reconstruct from stored metadata. Thus the crucial nondefault state is produced by current queue actions, not hand-injected.
3. Fault schedule: native reader loads/ACKs exactly100 tasks401..500. Before its next load, real queue.checkpoint removes first scope. Reader drains orphan then cursor becomes nil, while physical Activity502 and durable reader1 scope remain.
4. Repeat default processNewRange, checkpoint, notifyReaders and reader load three times: no additional persistence load/submission. Fault log: submitted100, reads1, deletion watermark502, row502 survives.
5. Healthy control with the same preparation and next read before checkpoint:101 submissions, reads2, including502. Reconstruction from persisted state also submits502; after its controlled ACK a real checkpoint physically deletes the final row.

Evidence: checkpoint-sqlite-final-tests.log (five cases PASS), checkpoint-sqlite-cursor-native-prep.log (earlier same preparation), reader-cursor-test.log from parent minimal native control, source file above, and standalone cursor-stalled.sqlite. An independent database/sql connection sees exactly row502, then a successful WAL checkpoint permits retaining the standalone DB. A separate Python process reads the saved DB after Go exits: transfer_tasks[(10,502,152)], shards[(10,1,132)], integrity_check=ok, recorded hash in cursor-stalled-independent-readback.json.

Observed impact is live reader logical inaccessibility with durable recoverability and physical row retention. This is not physical task loss. A later reload or suitable reader-list mutation repairs it. Under stable ownership and fair ordinary poll/checkpoint/Notify, no such repair is guaranteed. Full workflow/worker end-to-end stall is NOT reproduced: controlled scheduler ACKs establish queue boundary outcomes; workflow rows/actual Transfer executor are not part of this test. Sibling executor ordinary dispatch tests provide separate real-executor, mocked-Matching evidence. Task publication here uses real task persistence API but does not prove that501 outstanding dispatch obligations from one particular workflow arise in a real workload.

Model handoff: include both scope coverage and operational cursor reachability. A model representing only sets of ranges/predicates will miss CR1 because its durable scope coverage remains correct. Explore current split/merge/shrink/clear and partial-batch execution interleavings for other cursor-obligation mismatches; preserving an already established concrete source finding is separate from claiming a future MC search discovered it. Model progress assumptions must allow stable ownership and must not grant automatic reload as fairness compensation.
