# Instrumentation specification

Harness compatibility: the mandatory tag follows the installed harness-generation skill (`trace`). The complete six-scenario implementation adapter and its explicit coverage limits are recorded in `../harness/REPORT.md`. `MatchingLostReply` uses the actual timeout classification (`unexpected`) and retains the measured unexpected-error counter.

Revision `0c010ce5fe8c0180aa7573c72fe8fc87c6df7025`; Category A; SQL/SQLite WAL. Paths abbreviated in `base.tla`: Q=`service/history/queues`, H=`service/history/shard`, SQL=`common/persistence/sql`, M=`service/matching`. This document maps all 65 base actions one-to-one to 65 trace event types. Init and Endpoint are trace-control records. It describes the next harness phase; no implementation trace is claimed to have been collected by spec generation.

## 1. Trace event schema

One NDJSON object per modeled transition, globally serialized by a **controlled test schedule at the stated hook boundaries**, with mandatory `tag: "trace"`, `schema: 1`, contiguous `seq` starting at 1, `provenance: "implementation"`, `event`, `args` and full `post`. `Trace.tla` accepts explicitly labelled `synthetic-spec-test` fixtures only to test the adapter; those are not implementation evidence. Unknown events and missing fields fail; there is no tag filter or silent repair.

The first record is `Init`, with revision, `backend: "sqlite-wal"`, actual mapped constants and a complete independently observed initial state. Constants keys are exactly `task_count, owner_count, groups, slice_slots, exec_slots, snapshot_slots, batch_size, max_epoch, move_threshold, predicate_limit, shrink_keys, unexpected_limit, dlq_enabled`. Groups are stable namespace-group strings. Final `Endpoint` has `complete: true`, `independent_readback: true`, full `post`, and `readback` containing `range, owner, rows, workflow, matching, started, obsolete, dlq, completed, queue`. These assertions require actual independent readback evidence in the harness report; labels alone do not establish provenance.

JSON `post` is the record `s` defined in base, with numeric-key functions encoded as arrays. Owner/task/executable/snapshot arrays start at identity1. Reader arrays always have two entries, positions1/2 representing reader0/1. Sets are JSON arrays (order ignored); sequence order remains significant. Every base state field is mandatory, including fields unchanged by the current action. DecodeState converts only the declared set and reader-map shapes; full equality then rejects missing, extra or incorrect state fields. No field is checked conditionally on presence.

Old wrapper state is independent of a newly loaded wrapper for the same task. |
| `snaps[j].owner,epoch,data,phase,caller` | Request identity, PreviousRangeID, exact copied shardInfo queue state, store outcome and receipt, checkpoint versus unrelated writer. Preserve distinct outstanding snapshots and commit order. |
| `notice[o]` | Queue hint channel/test suppression ledger. Periodic poll is observed independently. A lost hint does not remove rows or reset reader cursor. |

Every event must also retain a sidecar evidence reference to raw store/log/hook observations. That provenance metadata is not a model state prediction. `post` is assembled by an independent observation reducer from those measured values; never call base helper operators, copy TLC states or calculate a predicted missing pending row/ACK/checkpoint to fill a capture gap.

## 3. Special considerations

1. Bootstrap uses a fresh controlled shard at the modeled first acquired epoch with no modeled rows or scopes. Observe that state independently or include the full allocation/publication/reconstruction prelude. Do not change TraceInit to accept arbitrary corrupted starting state. Normalize actual epoch/key values by an order-preserving mapping that preserves `[lo,hi)`, exact adjacency/full-batch boundaries, pending minima and disjoint allocation epochs. Keep the mapping manifest with traces.
2. Default cfg bounds are test bounds. Native batch100 needs batch100 and enough task identities, or a separately justified quotient preserving the full/partial branch. Prefer real queue tests with explicit small batch/threshold overrides for initial adapter validation. Production values and overrides must be in evidence. A transaction generating multiple modeled Transfer rows needs an atomic bundle extension before capture; do not emit multiple fake commits.
3. Each real semantic split requires its own event. Store commit and API reply must have different hooks; same for renewal and owner memory reset, source-reader split and destination merge, checkpoint scope snapshots and DELETE, copied shard metadata and its later store commit, Matching/DLQ effects and caller responses, Execute unlock and ACK, and each Clear cancellation. No silent actions are supplied to fill missing observations.
4. A reader SelectTasks batch is projected atomically under its reader mutex. For a controlled trace, capture the raw store page and hold relevant fault-schedule hooks so a concurrent DELETE/read-buffer window is unambiguous. If a complete real schedule requires a separate prefetched/read snapshot state, refine the model/adapter before validating it; do not reorder observations merely to make TLC accept them.
5. Move/split/merge/compact rebuild list elements and reset cursors; ShrinkSlices does not. Record the detached element's original identity and iterator state. Notify on immediate reader completion has no cursor repair; NoopReaderCompletionFn is the queue's actual callback. Capture reader1 as well as reader0.
6. Exact predicate bytes and monitor group-count inflation are outside this state projection. Capture raw predicate/group counts in side evidence, audit the threshold/byte quotient, and retain CR-2 tests. Do not compute groupsToMove from model set cardinality when implementation counters disagree; such a trace requires extending the policy/count abstraction first.
7. Matching acceptance is historical transport responsibility, not eventual workflow completion. Terminal Internal/DataLoss drop is a distinct observation. Stale/version-invalid work can be treated obsolete only with concrete workflow/stamp/replacement evidence. DLQ acceptance requires committed EnqueueMessage, not merely a queue-created result or an attempted write. Duplicate effects are allowed and their raw IDs should remain in evidence.
8. Independent endpoint readback must happen after the test establishes which calls have completed; drain or identify every outstanding request, explicitly state whether old-owner callbacks remain, then read shard metadata and Transfer rows on another connection. For recovery cases include actual post-AcquireShardComplete lists/cursors and post-reload dispatch. State the SQLite file, WAL/synchronous settings, revision, command, and relevant dynamic configuration.
9. Mandatory negative controls for the harness: mutate an ACK without accepted/obsolete/DLQ/terminal outcome; omit a pending original row; alter scope predicate or cursor identity; replace a volatile memory checkpoint with a falsely claimed durable checkpoint; truncate before Endpoint; omit an intermediate commit/reply event. Each must be rejected by TraceMatched/post-state checks. Test adapter rejection separately from semantic responsibility hunts, since CR-1 and terminal-drop policy can be real traces that intentionally violate extension properties.
10. Run from `spec/` with classpath including TLC and CommunityModules. Set `JSON=/absolute/path/to/trace.ndjson` for per-run selection; without it JsonFile is exactly `../traces/trace.ndjson`. Trace.cfg enables `PROPERTIES TraceMatched`. A successful synthetic fixture only tests the spec/JSON adapter; implementation convergence remains pending until complete real traces and their controls pass.

## Validation refinements

`ClearSlicesBegin` may continue to a later selected slice while the reader lock remains held and the preceding cancel loop is exhausted. Its snapshot includes the cleared preceding tracker. `ClearSlicesComplete` resets the cursor once after the loop. `SelectTasks` sidecars now include `selected_slice`, sampled from the actual loadSlice after iteration, preserving detached-object observations when nextReadSlice becomes nil. See `changelog.md` for debugger evidence. The atomic SelectTasks model covers successful active-shard admission; prefetched pages and partial read errors remain outside this projection.
