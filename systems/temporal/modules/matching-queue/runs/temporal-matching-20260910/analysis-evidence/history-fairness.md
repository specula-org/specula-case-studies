## Fairness implementation contract

1. **Identity/order.** Storage key is lexicographic `(pass,id)` (`fair_level.go:12-30`), separate from logical History work identity. IDs allocate monotonically through RangeID blocks (`fair_task_writer.go:102-115,143-151,247-259`). `pickPasses` uses each reader's pinned ack pass, per-key counter, stride `max(1,1000/weight)`; dither is configurable and false at this revision (`fair_task_writer.go:118-140`; `fairness_util.go:10-40`; dynamicconfig constants 1632-1638). Small-key default counter is exact map before the 100-key hybrid threshold (`counter/hybrid.go:27-64`; `counter/map.go:32-44`).
2. **Writer/ack atomicity.** One writer loop calls `getAndPinAckLevels`, picks passes, performs `CreateFairTasks`, calls `wroteNewTasks` only on nil error, then unpins (`fair_task_writer.go:155-226`). Reader lock pin is a separate action from store transaction. The pin remains effective through `newlyWrittenTasks` while readPending even after explicit writer pin drops (`fair_task_reader.go:54-62,394-406,607-615`). Never split backend transaction's row writes/RangeID condition into independently committed model actions.
3. **Deferred write/read merge.** One pending read loop snapshots readLevel/loadedTasks outside its lock for I/O, merges reads, then clears readPending and merges deferred writer tasks before allowing ack advance (`fair_task_reader.go:245-281`). A read starting while a write is pinned may observe/complete those rows before writer response; duplicate merge ignores already tracked loaded or acked entries (`451-469`).
4. **Memory boundary.** CoW merge occurs under reader lock; it combines outstanding entries and new observations, keeps first batchSize **loaded** tasks, and trims every loaded/acked entry at or above the cut (`434-537`). New writes above readLevel are ignored in memory unless atEnd is known. Reads <=ack and duplicates are ignored. Expired rows and remembered evicted acks become pre-acks. Acks do not consume memory slots. This differs from a simple `Len(outstanding)<=batchSize` invariant.
5. **Eviction/dispatch.** Trimming invokes `setEvicted` under reader lock, but may race with a task already removed by a poller; absent-on-completion is intentionally replayable, not immediately acked (`153-172,514-527`; `task.go:343-358`). Finite cache size 256 may forget completed levels and cause permitted duplicates. A cache eviction is not durable acknowledgement.
6. **Ack/GC/durability.** `advanceAckLevelLocked` pops only leading pre-acks while unpinned, starts async GC, then updates cached metadata (`613-636`). GC deletes `<ack.inc()` using a snapshot, with SQL row count versus Cassandra UnknownNumRowsAffected behavior (`680-729`). Metadata sync is independent (`fair_backlog_manager.go:217-232`). Reload initializes read/ack from persisted fair ack (`167-179`); memory ack can be ahead of disk and GC can precede metadata persistence.
7. **Completion/replacement.** Successful delivery or permitted drop becomes pre-ack. Transient/cancel/deadline failure returns task to matcher; other errors respool and only then complete original (`153-220`). If replacement ultimately fails, backlog manager sets skipFinalUpdate and unloads, retaining original below ack for recovery (`fair_backlog_manager.go:366-393`). Stable-owner progress requires eventual accepted store operations, eligible polls/History acceptance, processing of pending reads/completions, and finite interfering writes.
8. **Uncertain append.** Any writer error makes atEnd false and initiates reading; it does not rewind readLevel (`648-662`). A committed-error fresh row can fall below current readLevel because pass allocation uses ack, not read level. This alone is not accepted-work loss: failed enqueue returns error and caller may retry; failed respool unloads and original remains. `fairness.md:142-144` explicitly declines a success guarantee for timeout writes. Model acceptance and logical replacement, not conservation of all speculative rows.
9. **Documentation calibration.** `fairness.md:23-28` says “dispatched” below A; implementation also acks expired and explicit dropped records. Its `(A,R] in memory` wording must include tracked pre-acks and in-flight dispatched-but-not-completed tasks, not only tasks currently in matcher. It accurately describes the write pin and LWT-fencing intent (`185-218`, `132-162`). FairMaxReadLevel is diagnostic/best effort and explicitly not used for reader correctness (`db.go:636-639`), so do not infer an upper read bound from diagram M.

## Forward-looking extension questions after baseline calibration

### F-C1: Original completion resumes after successful re-spool and concurrent eviction

**Status:** source-derived candidate with a concrete permitted schedule; **not reproduced, not model checked, not trace validated**. It is a new interaction at the pinned code, not recreation of #8070/#11048. Keep it separate from the priority baseline; verify the concrete schedule through production queue/store before reporting a bug.

`completeTask` verifies original entry under the reader lock (`fair_task_reader.go:165-172`), releases lock for respool (`182-203`), then reacquires and calls `completeTaskLocked` without checking that the original remains tracked (`206-215`). Concurrent merge can evict original and lower readLevel (`514-542`). Completion then reinserts an ack above the lowered readLevel and decrements loadedTasks again. The existing missing-entry guard compensates only at callback entry, not after the asynchronous replacement write.

Concrete candidate schedule with a stable owner, one physical queue, one priority, fairness enabled, dither false, `getTasksBatchSize=3`, `getTasksReloadAt=0` (valid less-than-batch setting), default small-key counter:

1. Initialize a fresh empty queue and allow its empty read to establish atEnd=true. Before creating pollers, successfully spool same-key A=(1000,1), B=(2000,2), C=(3000,3); writer bypass merges these within the three-task capacity without losing atEnd. Three concurrent worker polls take A/B/C, but none completes yet; reader still tracks three loaded entries. Tasks have no expiry or expire beyond the finite scenario.
2. C's History call is rejected by a **namespace-scoped RPS limit**. This is a real interface response (`common/rpc/interceptor/namespace_rate_limit.go:25-28,138-139`; History wiring `service/history/fx.go:341-364`). Namespace ResourceExhausted is not system-transient (`common/util.go:204-207,338-353`), and activity poll feeds it to completion (`matching_engine.go:1109-1115`), so C takes the respool path.
3. C callback passes membership check and unlocks; delay it before its replacement enqueue. The single writer commits fresh-key Y=(1000,4), Z=(1000,5), both successfully accepted. Merge retains A/Y/Z and evicts B/C. Set readLevel=(1000,5), atEnd=false, loadedTasks=3. Polled tasks can be evicted from reader tracking; `setEvicted` does not cancel their History RPC.
4. Then the same single writer commits C's replacement R=(4000,6). It is above readLevel while not atEnd, so it remains durable but is not merged. C callback resumes, inserts ack C without revalidation, and decrements loadedTasks to 2 although A/Y/Z are still loaded.
5. Complete A/Y/Z successfully before a subsequently spawned read has processed its result. The last leading ack can now move ackLevel to C, across evicted B. B's delayed namespace-scoped RPS rejection sees its entry missing and returns without respooling. Eligible B has never had accepted History start or replacement. A successful normal SyncState then supported unload/reload can skip B. For physical deletion, additionally satisfy the real GC timer/count trigger (`fair_task_reader.go:690-695`) and process the captured bound; do not force a deletion outside Matching's GC path.

The producer operations above are serialized Y/Z then R; no concurrent writes to the single writer are assumed. Read goroutine scheduling is genuinely independent, so a newly scheduled read need not install its result before the next completion. A negative loadedTasks softassert logs without aborting (`common/softassert/softassert.go:28-33`); the extra backlog-age decrement clamps to zero (`backlog_age_tracker.go:24-37`) and does not cancel the callback. Required validation must observe B's accepted enqueue, absence of History acceptance/replacement, actual eviction, original callback resume, durable ack/GC, and owner reload. Counterexample checks should preserve task identity across R and C rather than treating every row as new work.

### F-C2: Nonterminal short Cassandra pages interpreted as end of fair backlog

`db.GetFairTasks` requests `UseLimit=true` but sends no page token (`db.go:725-735`). Cassandra v2 uses a CQL LIMIT and explicit driver PageState, and returns a nonempty continuation token (`matching_task_store_v2.go:146-172,205-210`). Fair reader decides end solely from `len(tasks)<batchSize` and ignores the token (`fair_task_reader.go:303-315`), after which atEnd suppresses reads (`234-237`). If the **executed backend** can return a successful short/empty nonterminal page on this exact LIMIT query, the endpoint inference is unsound; read/merge/ack interactions then require checking. This is conditional: no Cassandra/Scylla run was performed here. Fair schema has no per-task TTL, so use actually permitted explicit-GC tombstones plus lagged ack/reload or backend response-size behavior, not fabricated row expiration. Coordinate with priority paging investigation; no independent current bug claim.
