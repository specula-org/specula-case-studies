## 1. Trace event schema

Write complete NDJSON runs to `../traces/<scenario>.ndjson` relative to this directory. `Trace.tla` defaults to `../traces/trace.ndjson`; select another file with the `JSON` environment variable. Load both `tla2tools.jar` and `CommunityModules-deps.jar` for `Json` and `IOUtils`.

Each line has the strict outer envelope `{tag: "trace", ts: <observed UTC timestamp>, record: <record below>}`. `Trace.tla` validates that envelope before decoding the unchanged state schema.

The first tagged record is `bootstrap` with `seq=0`. Its exact fields are `tag`, `seq`, `event`, `source`, `revision`, `queue`, `config`, and `post`. `tag` is `temporal-matching`, `source` must be `implementation` for `Trace.cfg`, and `revision` must be the pinned SHA. `queue` has `namespace`, `physicalName`, `partition=0`, `subqueue=0`, and `taskType` (`workflow` or `activity`). Capture these independently from each request/store key; never fill a mismatching event queue key from the header.

`config` has exactly: `backend="sqlite-v1"`, `useNewMatcher=true`, `enableFairness=false`, `priority=3`, `writeBatchSize=1`, `owners`, `work`, `callIds`, `pollers`, `startIds`, `initialOwner`, `rangeSize`, `batchSize`, `reloadAt`, `deleteBatchSize`. Actor/caller/poller IDs are dense integers starting at 1; assign an **owner lifetime** ID, not just a host name. Work strings are a canonical, collision-free encoding of actual `(namespace, workflow, run, task type, scheduled event ID, stamp)`; storage TaskId and History RequestId are separate identities. Preserve raw-to-model UUID mappings, allowing a new alias for every distinct start UUID. Storage IDs/range IDs are actual numeric values, not arbitrary compacted row ordinals.

Every action record has exactly:

```json
{"tag":"temporal-matching","seq":1,"event":"AddTask","node":1,
 "queue":{"namespace":"observed namespace","physicalName":"observed name","partition":0,"subqueue":0,"taskType":"workflow"},
 "args":{"a":1,"w":"canonical complete work identity","o":1},
 "post":{"calls":[{"pc":"offer","owner":1,"work":"canonical complete work identity","buffer":"none","response":"none","receipt":"none"}]}}
```

`seq` strictly increments in the observed causal order. `node` is the owner lifetime determined by the action's `o`, caller's owner, or poll attempt's owner; independent expiry/obsolescence uses 0. Parameters in `args` are listed per action below. `result` values and `reply` classification must come from captured implementation outcomes; never choose them by searching for a model path. `launch` is the actual GC decision.

Store observation arguments are mandatory as listed in the table: `tasks`/`deleted` are arrays of actual decoded `{id,work}` rows; `min,max,limit` are the actual store request fields; `expectedRange` and `actualRange` come from the locked transaction condition and stored row before the operation. They are checked against the captured operation and model state. `RecordTaskStarted` also carries the actual History-received `work` and `request`. These values must not be reconstructed from the caller/request ledger alone. SQLite audit triggers can record actual inserted/deleted IDs and TaskInfo in the same transaction; rollback must roll back the audit rows too. Observe SELECT rows directly. A separate quiescent readback reconciles the resulting durable state.

`post` must contain **exactly** the groups listed in the mapping table. Each supplied group is a complete snapshot in the encoding below; no optional per-field validation. All fields in each implementation record are compared. The final `TraceEnd` record has `node=0`, `args={}` and all nine groups. It is an observation seal after the complete scenario and independent end-state readback, not an implementation action. `TraceMatched` is enabled and all events, including the seal, must be consumed. There are no silent actions.

`pc`, local phase labels, lock-wait labels, FIFO/matcher registration membership and callback ownership are instrumentation observation state derived solely from named executed hooks. `cacheRead/cachePoller` retain the actual blocked call's local value. An external collector can assemble unchanged portions of a group from previously recorded observations, but must not advance a cursor, invent a row, classify a missing callback, infer commit from success expectations, or run the model to fill missing implementation state. Every mutation of the observed groups needs a hook. `audit` and `cursor` are TLA observer variables computed from these already validated actions; they are not claimed to be implementation fields and are not supplied as authoritative trace data.

Use actual neutral values from `IdleWriter`, `IdleReader`, `IdleMetadata`, `IdleDispatch`, and `IdleCall` when a frame has not yet existed; these are explicit observer lifecycle markers. Include zeros and false booleans in JSON. Empty sets and sequences are `[]`; `catalog` is an array, and `history` is a string-keyed object. No duplicate set elements or catalog IDs are accepted.

### Error classification

`CreateTasks.outcome`: `commit` means independently confirmed atomic commit; `condition` means actual range-condition rejection; `limit` means a persistence/concurrent limiter rejected before the store; `noCommit` means a independently established failed transaction. Matching-facing `reply` is respectively `ok`, `condition`, `definite`, or `unknown`; a confirmed commit can return `unknown`. Queue shutdown is **not** one of the definite store outcomes. See `db.go:677-697`.

History `result`: `ok`, `already`, `obsolete`, `transient`, `respool`, or `busy`. Transient includes the actual service-client transient/context classification (`common/util.go:204-208,338-371`, `pri_task_reader.go:123-132`); `busy` is namespace-scoped BUSY_WORKFLOW and separately triggers sync fallback (`task_queue_partition_manager.go:707-714`). Ordinary sync-match errors return errors rather than spooling. The model does not certify Internal/DataLoss drops as valid disposal; stop and investigate those observed outcomes under CR-2. Expiry never deletes SQL rows by itself.

## 3. Special considerations and complete-scenario handoff

**Initial state:** start from a fresh empty V1 queue, first range 1, reader/cache/durable ack 0, writer next ID 1/end RangeSize, and the reader's initial wake pending. Observe and settle the real empty V2 draining setup triggered at `db.go:217-218`/`physical_task_queue_manager.go:380-460` before bootstrap. The model does not fabricate a flag disabling that setup. If the real bootstrap differs, record the complete initial state and deliberately adjust Init and its capture together; do not overwrite the observation to match Init.

**Ordering and locks:** instrument inside the existing atomic regions before releasing the lock. The observation sequencer is a leaf lock and must never acquire reader/DB/matcher locks in reverse order. Capture touched local fields at the real hook; assemble other observed groups outside source locks. Use controllable gates to hold *response delivery* separately from store/read/History effects. Do not infer commit order from API return order. SQL transactions remain atomic. For SQLite, instrument the transaction commit/SELECT/delete snapshot and independently query the real file-backed database at controlled quiescent points. Preserve the captured request bounds when pausing an old owner's read or delete. No range fence belongs on read/GC.

**Crash evidence:** a killed process cannot emit post-crash callbacks. Emit Crash, DiscardCrashedWriter and PollerDisconnect from the external test driver/observer; independently resolve submitted store/History operations. Use a fresh manager lifetime to reacquire via real RenewLease. A fake matcher or fabricated GetTasks reply cannot establish durable recovery. Unknown outstanding outcomes must remain unresolved evidence gaps rather than being labeled noCommit.

**Identity controls:** derive `catalog.work` from actual stored TaskInfo, not from the Add request ledger alone. Verify replacement data against original work identity. Observe the actual queue tuple at every DB/reader event. Preserve History RequestId separately from TaskId and scheduled-event/stamp identity. Validate a copied trace with one work identity changed, another with a queue/subqueue/bound changed, and another with a required post field removed; all must be rejected. Synthetic fixtures under `checks/` only test wrapper plumbing and never count as implementation controls or complete scenarios.

**First real traces:** (1) durable enqueue/read-or-bypass/start/ack/metadata/GC with independent end readback; (2) paused GetTasks result, successful bypass, out-of-order finishes, duplicate filtering and stale gap, followed through draining and reload; (3) committed-but-error initial write, caller retry/wake or reload; (4) uncertain replacement, retry exhaustion/failed replacement, supported unload, fresh owner and final History acceptance; (5) paused old-owner write/metadata/GC across takeover, including definite range rejection; (6) sync acceptance/lost History reply versus lost Worker receipt; (7) retained all-expired SQL rows and observed cleanup behavior. Do not stop after a passing prefix. Record any remaining observed mismatch with its exact event and source state.

**Verification handoff:** run these complete traces with real queue + store, then the bounded `MC.cfg` baseline (3 work identities, 6 allocated records, 2 owner lifetimes/pollers, range size 2; initial resource proposal 30 min/8 GiB), then four targeted hunt cfgs. Report exact cfg/hash, state/depth/time counts and INCOMPLETE for a timed-out search. `MC_live_S4.cfg` has explicit processing/stability assumptions and no resource-state constraint or symmetry; it is not a guarantee under absent pollers, endless interference, or failure to reacquire. Only after core calibration advance to the backend paging/fairness gates documented in `gated-extensions.md`.

**Scope limits:** write batches are singleton and the append channel is abstracted by a FIFO with capacity at least the bounded number of submitted requests; channel-full rejection is outside this selected configuration. No global order, weighted fairness, worker-version routing, legacy migration work, multi-cluster behavior, exact approximate-backlog counts or History internal outbox is represented. New outer start UUIDs use fresh aliases; the MC pool can recycle IDs that no active request/accepted History record can compare against. History start acceptance is a durable-or-recoverable interface obligation, including the explicitly external speculative-work recovery contract; Worker delivery is tracked separately.

## Root-validator extension

`ValidatorBase.tla` / `TraceValidator.tla` add ValidationMatch, ValidationResult and ValidationDone. Complete owner/dispatch/history state and the independently observed validationHolds map (poller, record ID, context canceled at handoff) are checked. Negative validity requires an uncanceled request at handoff; canceled calls are not evidence of obsolescence. TraceEnd validates an empty holder map. Native source hooks and validity-request evidence are in the harness; the actual age guard is waited, not synthesized.
