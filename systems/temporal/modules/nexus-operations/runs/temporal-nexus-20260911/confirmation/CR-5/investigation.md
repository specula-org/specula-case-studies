## Source Evidence

- `service/history/hsm/nexusoperations/workflow/commands.go:268` checks buffered terminal Nexus events before rejecting a cancel for a missing/deleted operation.
- `service/history/hsm/nexusoperations/workflow/commands.go:302` records `NEXUS_OPERATION_CANCEL_REQUESTED` even when terminal completion is buffered, so workflow replay observes the cancel-request command before the buffered terminal event is flushed.
- `service/history/hsm/nexusoperations/events.go:164` deletes the operation HSM child when a completion event is applied.
- `service/history/workflow/transaction_impl.go:202` notifies mutation listeners for `OperationPossiblySucceeded` errors even when the caller receives an error.
- `service/history/shard/context_impl.go:1541` treats default persistence errors as uncertain and forces shard reacquisition, which makes subsequent reads distinguish committed from failed writes.
- `common/persistence/faultinjection/fault.go:43` and `common/speculatrace/trace.go:140` provide the existing `ExecuteAndTimeout` fault used to emulate a committed persistence write that returns timeout to the caller.

## Reachability

The reproduction uses only normal frontend/history APIs plus the existing persistence fault hook:

1. Start a workflow through the SDK client.
2. Complete the first workflow task with a real `ScheduleNexusOperation` command.
3. Let the external Nexus endpoint accept the start and return an async operation token.
4. Poll and hold the workflow task generated by `NEXUS_OPERATION_STARTED`.
5. Send the real Nexus completion callback while the workflow task is held, so the terminal event is buffered.
6. Inject `ExecuteAndTimeout` specifically on the `UpdateWorkflowExecution` write that contains the buffered terminal event.
7. Close the shard and reload mutable state from persistence.
8. Complete the held workflow task with a real `RequestCancelNexusOperation` command against the original scheduled event ID.
