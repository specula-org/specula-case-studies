# Algorand BA* Spec Validation Changelog

## Round 1 - Trace Validation

### Spec / wrapper fixes
- [fix] `PersistedBeforeBroadcast` invariant: nested the multi-binding `\A i, vt \in UNION { ... : i ... }` into separate `\A i : \A j, r, p, st : \A vt \in ...` so TLC parses it correctly (base.tla).
- [fix] `Init.round`: start every server at round 1 to match the test's `testLedger` (`nextRound = 1`); add comment.
- [fix] `Init.ledgerCertified` simplified to all-`Nil`; no need to inject a "genesis" since round 0 is pre-genesis.
- [fix] `ProposeBlock`: inline the `pinnedLowest` update; calling sub-action `UpdatePinnedLowest` would conflict with `ProposeBlock`'s own `inFlight'` / `messages'` updates via overlapping UNCHANGED clauses.
- [fix] `ReceiveProposal`: inline the `pinnedLowest` update; same reason.
- [fix-spec] `IssueCertVote`: do NOT transition step. The implementation calls `issueCertVote` from the `softThreshold` handler (`player.go:405`), which does not change `p.Step`. The previous spec spuriously bumped step to `StepNext`, causing post-state mismatches with traces.
- [fix-spec] `PersistState`: drop the "must diverge from persisted" precondition. The implementation re-fires `persistState` after every action-handler boundary even when nothing changed; the spec must be idempotent.
- [fix-spec] `TraceSpec`: add `WF_<<l, vars>>(TraceNext)` weak-fairness so `TraceMatched` (`<>(l > Len(TraceLog))`) does not produce trivial stuttering counter-examples after the last trace event consumes its action.
- [fix] `TraceValue`: collapse all concrete digest strings to symbolic `"v1"`. The trace records real block digests that aren't in `Values`; mapping them all to a single token keeps `Values = {"v1"}` finite without losing replay fidelity.
- [fix] `OptInt` / `OptStr` helpers in `Trace.tla`: tolerate missing optional fields in JSON (Go's `omitempty` drops zero-valued `thresholdPeriod`, `thresholdValue`, `thresholdType`, `installedValue`, `decision`).

### Wrapper fixes
- [fix] `BroadcastVoteIfLogged`: relax to not require `inFlight` membership. The test runs ONE pseudonode with N keys; each per-key broadcast is tagged with the key as `nid` but the vote was generated by the single "local" player. The wrapper now sends the wire message and records the vote in `votesSeen[i]` directly.
- [fix] `ProposeBlockIfLogged`: same relaxation for the same reason.
- [fix] `IssueSoftVoteIfLogged`: use `ValidatePostStateLoose` (only round/period). The trace captures state BEFORE `p.Step = cert` transition, so state.step = 1 (soft); the spec's atomic transition leaves step' = StepCert.
- [fix] `Trace.cfg`: `Server` must use strings (`{"n1", ...}`) not model values to match JSON-deserialized `nid` strings. Remove `PersistedBeforeBroadcast` invariant (broken by the single-pseudonode model); add Trace_diverse.cfg / Trace_normal.cfg / Trace_committee.cfg for the larger traces (committee == Server abstraction means larger Server raises the threshold beyond what the trace's per-key vote count can satisfy).
- [fix] Removed `SilentProposeBlock` and `SilentReceiveVote` silent actions; with the new BroadcastVote wrapper directly populating `votesSeen[broadcaster]` and explicit `ReceiveVote` events delivering votes to `local`, these silent actions caused state-space explosion (one branch per (server, message) pair).
