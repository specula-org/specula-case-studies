## Exploration-bound review

The MC wrapper retains the original budgets on injected operations and leaves their completion paths reactive. In particular, Restart requires `~raft[n].alive`; only the budgeted MCCrash path stops a node in MCNext. The base's Stop is exactly a Crash alias, so it does not introduce an uncounted restart cycle in this wrapper. This is an abstraction of stopped-operation behavior, not a validation of Node's full stopped-method return matrix. Restart's incarnation counter therefore does not by itself make this configuration unbounded. No state projection, new cutoff, or fault-budget reduction was introduced to accelerate the check.

The term/log/message constraints still limit what the MC configurations explore; they are not assumptions establishing correctness outside those limits. A complete finite-state argument and exhausted reachable graph are not claimed from this review. Actual execution coverage is reported separately from property wiring and source correspondence.
