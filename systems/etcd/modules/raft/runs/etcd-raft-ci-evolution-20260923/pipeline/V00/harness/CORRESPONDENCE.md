# Harness correspondence and remaining scope

This harness targets the supplied upstream V00 production source, `d58d5d159ae1a1f644a10003f2d8b3b807cd0b3a`, with the approved build-only go.mod/go.sum adaptation. It uses the run's approved guidance and pinned Specula harness/trace methodology. No other experiment, later source, target defect history or shared memory was used. The only production-file edits are 18 observational hook lines in raft.go/node.go. Protocol state, decisions, public call arguments and network payloads are not repaired by instrumentation.

## Observation and caller contracts

This is Category A: one mutex-protected NDJSON writer per scenario, real UTC timestamps, immutable numeric node identities, a typed sequence/set/function/bag codec and full post-state equality. Every `TraceNext` consumes an actual event by calling its complete base action, then compares all six components (`raft`, `disk`, `ready`, `application`, `requests`, `wire`). There are no silent transitions or missing-field allowances. The four excluded accumulated core oracle sets are recomputed by the model, as specified in the input contract.

All Raft execution uses public Node/RawNode interfaces. Existing TestRawNodeStart, TestRawNodeProposeAndConfChange and Node restart tests supplied the constructor/Ready patterns; their injected states or substituted Step functions are not reused. The new adapter supplies observability and caller stages absent from those tests. Transport only publishes actual Ready messages, then delivers/drops/duplicates identical instances. Snapshot status refers to an actual published snapshot. The network does not synthesize protocol messages.

The application is a symbolic ordered command-history state machine. Its deterministic configuration reducer is caller code; actual committed configuration entries invoke the real ApplyConfChange. Bootstrap reapplication, canceled callbacks, neutralized proposals and application lag remain visible. Request handoff/API return do not imply a committed or applied result. Completed reads use actual delivered ReadStates and an inclusive application fence.

The durability adapter writes real JSON images through write, file Sync, rename and directory Sync. StartPersist writes an unpublished candidate file; CompletePersist makes that image durable and rereads it before observation. MemoryStorage ApplySnapshot/Append/SetHardState are separate visibility events. Snapshots contain the application's real entry history and configuration. Crash discards the live core and caller work; restart loads only completed files into a new real core. Dead-node fields are a frozen last observation, not a recoverable live object. This models logical crash/restart, not OS process or physical WAL failure behavior.

`AppliedAdapter` checkpoints actual application history and supplies its coherent ConfState through InitialState plus Config.Applied. `Replay` instead restores snapshot configuration and replays committed entries through ordinary Ready/application. MemoryStorage alone is not claimed to provide the application checkpoint. Both are exercised. Strict/Atomic is the main persistence mode. The separately labeled SameBatch case publishes a leader's new appends before same-batch fsync only when HardState is unchanged; followers persist before publishing ACKs. Sequential caller application-before-Advance and permitted early-Advance-before-application schedules are both observed.

## Adapter changes to the input specification

1. The supplied envelope used `tag: "specula"` and rejected timestamps. Trace.tla and trace_codec.py now require the skill's `tag: "trace"`, with a real `ts`; flat action names and the complete typed payload are preserved. instrumentation-spec.md and the existing synthetic-fixture generator were aligned. Old synthetic outputs are retained as historical codec-only artifacts, not implementation evidence.
2. The base's unit bootstrap/no-op size abstraction could not represent the harness's meaningful multi-entry batching with exact protobuf sizes. Three nullary defaults (`BootstrapPayload`, `BootstrapEncoded`, `EmptyEncoded`) preserve the previous MC defaults of one. Trace.cfg overrides them with measured sizes 6, 14 and 6. Normal/config entries retain actual Data length and Entry.Size independently. The audit records every observed kind/payload/encoded combination and verifies the one-byte term/index domain (<128). No payloads or size classes are coerced to make comparisons pass.
3. `InitialTimeoutAssignments` names the base's original Cartesian assignment set without changing it. Trace.cfg selects the one assignment recorded in Init and explicitly checks the original timeout interval. Full Init equality already requires every timeout to equal that observation, so this removes redundant enumeration without changing trace acceptance. Base/MC initialization still enumerates every original assignment.

No core protocol transition or safety predicate was changed. All canonical Trace.cfg invariants and TraceMatched remain enabled. The supplementary OracleTrace module reads observed state and constructs only the application/read/Advance histories needed to test named predicate sensitivity. Its results are explicitly distinct from full reference-action replay.

## Explicit remaining coverage gaps

All mapped event names being visited is not comprehensive branch or interleaving coverage. The harness does not yet cover arbitrary Node channel races, cancellation after handoff, every stopped-method return, mixed Node/RawNode multi-node groups, arbitrary batched proposals via public Step, zero-length normal client payloads (the current command codec reserves eight bytes for identity), storage reads interleaved with concurrent compaction inside a core call, asynchronous commit-only MustSync=false durability, independent torn/interrupted multi-part persistence, all allowed publication/Advance permutations, empty or reused read contexts, removal of the active leader, unknown-removal legality, or fatal-storage/panic transitions. Fatal test execution would fail the Go run and leave an incomplete trace; it is never converted to `fatal=""` on a fabricated successful event.

Parallel persistence interpretation and broader SameBatch follower/snapshot interpretation remain unresolved, as in the supplied model. The targeted five-predicate negative checks establish sensitivity to their mutations, not completeness of those predicates. Missing persistence data is rejected by full correspondence; the supplementary six predicates do not independently assert durability completion fidelity. ReadApplication is checked on real positive reads but has no separate fence mutant in this batch.

Progress is demonstrated only for the explicitly serviced finite scenarios. No temporal liveness theorem, exhaustive protocol safety result or post-convergence model-checking hunt is claimed by this harness task. Broader initialization and researcher model-quality acceptance still need the remaining model/interface coverage work. No CI `current` pointer, verdict or property list was manipulated, and nothing was published.
