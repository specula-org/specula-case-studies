### Lifecycle map

3. ServerRunner applies optional outbound filters after communicator return, then returns the assignment. 4. The ordinary client fetches, executes and submits serially while a heartbeat/abort path can run independently. The in-process backend gives the trainer its model and restores assignment round on the result; the client runner restores assignment task name/ID and cookie jar (`nvflare/private/fed/client/client_runner.py:225-234,520-588`; `nvflare/app_common/executors/client_api/in_process_backend.py:153-249`).
5. Server submission filtering and workflow/identity checks precede communicator dispatch. BaseModelController checks return code, converts and invokes FedAvg's consumer; definitive acceptance is then published. Receipt is stamped after callback processing (`nvflare/private/fed/server/server_runner.py:460-570`; `nvflare/app_common/workflows/base_model_controller.py:251-294`; `nvflare/apis/impl/wf_comm_server.py:448-521`).

The task monitor evaluates receipt/status/death policy, removes terminal tasks and records bounded received-task history, then performs done/cleanup processing (`nvflare/apis/impl/wf_comm_server.py:1064-1155`). FedAvg independently observes queue length, finalizes its aggregate, updates/saves and starts the next round (`nvflare/app_common/workflows/fedavg.py:223-259`).

## Phase 3 — Source findings and adversarial cross-checks

Here “adversarial” means challenging the reasoning with ordinary functional schedules and compensating source paths, not hostile participants or exploitation.

### MC-1 — Partial consumer effects survive a negative acceptance decision

**Status:** source-supported candidate; runtime reachability/consequence and model verification pending. **Potential impact if confirmed:** Medium functional model/accounting integrity. **Scope:** built-in FedAvg; one concrete ordinary failure boundary requires `enable_tensor_disk_offload=True`, streamed PyTorch result payloads (e.g. `server_expected_format=ExchangeFormat.PYTORCH`) and an active Cell. Default NumPy exchange bypasses offload; the flag alone is insufficient (`docs/design/tensor_disk_offload.md:11-15,51`; `nvflare/app_opt/pt/decomposers.py:43-75`).

The helper increments key statistics before materializing a value, then updates each key's total/denominator before processing the next. History is appended only after the entire loop (`nvflare/app_common/aggregators/weighted_aggregation_helper.py:168-224`). FedAvg additionally adds all parameters before processing metrics and increments its callback count afterward (`nvflare/app_common/workflows/fedavg.py:299-330`). Ordinary materialization/metric/arithmetic failure after prior successful work can therefore leave different subsets in totals, histories and callback counts.

BaseModelController catches a consumer exception, leaves `accepted=False`, publishes the after-accept event and clears result references (`nvflare/app_common/workflows/base_model_controller.py:281-294`). There is no state rollback. The communicator still stamps receipt, so all selected processing attempts can let BcastTaskManager return OK; FedAvg reads residual helper state and updates/saves (`nvflare/apis/impl/wf_comm_server.py:521`; `nvflare/apis/impl/bcast_manager.py:64-66`; `nvflare/app_common/workflows/fedavg.py:233-259,346-364`).

**Compensations checked:** current event ordering is correct; helper/communicator locks serialize normal callbacks; empty results are skipped before mutation; invalid step weights are sanitized; unsupported metrics are filtered; helpers reset next round. None undoes earlier writes from a failing consumer in the current round. The return-code error policy runs before the consumer and does not see its later exception. The model must allow ordinary failure at actual operations rather than fabricate malformed parameter types.

**Verification handoff:** MC-1 tracks applied contribution provenance per key, history, definitive acceptance and save. A later local functional regression should retain real helper/controller/communicator logic and inject a controlled ordinary interface failure, comparing pre-mutation failure and normal success. Benign arrays alone do not validate the actual lazy-I/O path; use supported PyTorch offload values and the corresponding configuration. Keep conventional receiving content filters out of that variant (`docs/design/tensor_disk_offload.md:97-108`); MC-2 has a separate outbound-filter variant. No such test was run here. Existing `fedavg_test.py:942,1504,1528` tests skip/decision/conversion paths; those do not establish partial-state rollback.

### MC-2 — Queue-empty observation loses abnormal termination policy

**Status:** source-supported cross-layer candidate; runtime consequence and the exact abnormal-completion contract remain pending. **Potential impact if confirmed:** Medium incomplete-round commit or misleading ordinary continuation. **Concrete first variant:** a configured outbound filter fails after another selected client has already supplied a valid accepted result.

ServerRunner catches the ordinary outbound filter exception, calls `handle_exception`, and replies TRY_AGAIN without triggering run abort (`nvflare/private/fed/server/server_runner.py:333-356`). Communicator cancellation only marks the whole task CANCELLED (`nvflare/apis/impl/wf_comm_server.py:372-390,794-812`). Its monitor removes terminal tasks and queue length becomes zero (`:1067-1109,786-792`). FedAvg leaves its loop, finalizes the nonempty partial aggregate, updates/saves and can start another round without reading the cancelled status (`nvflare/app_common/workflows/fedavg.py:223-259`). ServerRunner normal return has no task-status compensation (`nvflare/private/fed/server/server_runner.py:130-183`).

**Compensations checked:** incoming filter/worker non-OK results follow a different return-code path and can panic under default dynamic tolerance; uncaught controller exceptions panic; new submissions to a terminal task are dropped; normal callback completion precedes monitor removal. These do not supply a status decision to the swallowed outbound-filter failure. Empty aggregation might fail later, so the primary candidate uses a nonempty valid accepted subset rather than relying on empty-model persistence.

**Contract boundary:** default “all selected responses” is a receipt contract, not “all contributions accepted.” `ignore_result_error` documents client return-code policy, not a complete CANCELLED/CLIENT_DEAD-to-round policy. The proposed property checks ordinary save/next ROUND_STARTED/normal-finish outcomes with outstanding responses under a declared policy; task-status logging is already present and is not the missing observation. Before interpreting a model violation as an implementation defect, validate whether partial continuation is permitted for that termination class. No instant callback stop or rollback-on-cancel property is proposed.

**Verification handoff:** separate terminal-status write, callback completion, retirement, workflow observation and save/advance, preserving both communicator and runner locks. Default timeout stays zero. Explore outbound-filter CANCELLED first; any ERROR or CLIENT_DEAD variant needs its own concrete source path and policy conditions. TV-1 maps both MC targets to future local regression evidence.

### Explicit exclusions and rejected interpretations

1. **Current acceptance event still precedes conversion/consumer:** contradicted by current `base_model_controller.py:263-294` and fixed #4907. Only distinct partial-state effects enter MC-1.
2. **Receipt/transport ACK proves contribution acceptance:** contradicted by callback/receipt order, BcastTaskManager and server command ACK mapping. Never an invariant.
3. **Result callback freely races another result or task retirement:** compensated by `_controller_lock` and task `cb_lock`; only source-permitted independent actions are admitted.
4. **Entire monitor is mutually exclusive with callbacks:** false; death/policy observations precede locking `check_tasks` (`wf_comm_server.py:1046-1062`).
5. **Broadcast snapshot occurs at scheduling, or every client gets a deep body copy:** false (`wf_comm_server.py:305-370`; `shareable.py:157-173`). First-client freeze and shared filter policy are modeled.
6. **Shared quantization body necessarily corrupts later targets:** #3222/quantizer's data locks and flag explicitly implement shared first transform; per-client custom copies are a documented responsibility. No alias-only defect claimed.
7. **Completed-history eviction necessarily reaggregates late data:** unknown current Recipe path lacks the consumer callback. Cache limit is recorded, without restoring pre-#4772 behavior.
8. **Cancellation rolls back accepted contributions, removes tasks immediately or instantly stops all callbacks:** unsupported. Model status marking, admitted work and drain separately.
9. **Residual task-done callbacks must run in finalization:** #4493's discussion and `wf_comm_server.py:856-860` deliberately distinguish teardown from normal monitor callbacks.
10. **Waiting API implies all task-done effects complete:** `wait_for_task` can exit on terminal status before done marker (`wf_comm_server.py:1189-1212`); default FedAvg does not depend on a done callback. Semantic reference, not a separate current defect.
11. **Multi-standing-task resend list duplication is reachable in the default training loop:** the observed generic code candidate requires another standing task (`wf_comm_server.py:222-264,349-358,1106-1109`). Current Recipe has one. Recorded in communicator audit, excluded from this model; no fabricated custom event creates the precondition.
12. **All-skipped contributions, missing metric keys or absent metrics alone prove a bug:** skips/metric suppression/per-key denominators are explicit (`fedavg.py:268-273,308-326`; `weighted_aggregation_helper.py:20-71,201-216`). Do not require all targets to be accepted.
13. **Current host memory/convergence/HA/admin-status issues can be imported into the round protocol:** excluded by the task scope. Historical reports remain qualified context only; numeric arrival-order rounding is documented, while FULL/DIFF representation ambiguity is separately TV-2.

## Phase 4 — Modeling handoff and coverage limits

The [brief](modeling-brief.md) provides five mechanism-based Scenarios and the required model/do-not-model, extension, invariant, pending-verification and reference sections. Only **MC-1 and MC-2** receive dedicated model-checkable findings. They concern present unaudited composition: retained aggregate effects after consumer failure and abnormal task retirement followed by ordinary workflow outcomes. Known fixes remain reference controls. TV/CR candidates are retained without falsely elevating them to formal findings.

Start with a symbolic two-client/two-round/two-key model; use a three-client extension only for selected-versus-unselected/dead-policy distinctions. These are proposed bounds, not runs. Keep source behavior in actions, including queue-empty progression and incremental writes; put desired contracts in properties. Do not make violations unreachable by assuming accepted equals applied, no failures after first mutation, or only-OK retirement. Preserve all real locks, while allowing independent death/policy/abort observation.
