## Issues Found

- **High — The before-send hunt models the wrong exception-propagation behavior.** `BasePrepareTaskDataFailure` (`base.tla:161-165`) says an ordinary before-send event-handler error marks the task `ERROR`; `MC_hunt_s4_prepare_error.cfg:1,18,27` explicitly selects this mechanism. The selected callback is `_prepare_task_data`, which only calls `fire_event_with_data` (`nvflare/app_common/workflows/base_model_controller.py:213-228`). Event delivery reaches `fire_event_to_components`, whose `try/except` catches ordinary handler exceptions, logs them and stores them in the context without rethrowing (`nvflare/apis/utils/event.py:54-84`; dispatch connection at `nvflare/private/fed/server/run_manager.py:103-104` and `nvflare/private/event.py:18-29`). Thus a normal handler exception does not reach the communicator's callback catch at `nvflare/apis/impl/wf_comm_server.py:281-293`. The generic callback catch exists, but it does not establish the specific mechanism claimed here. **Required:** model the swallowed handler-exception outcome, or identify and separately declare a supported failure that actually escapes this callback. Update the hunt, source annotation and `instrumentation-spec.md:67` together. This is a specification issue, not evidence of an NVFlare defect.

- **High — Monitor actions require iterations that the implementation does not execute.** `WFCommMonitorBegin` always sets `mon.pending = Clients`, and `WFCommCheckDeadClient` must remove each client before `WFCommDeadCheckDone` can run (`base.tla:473-490`). In source, `_check_dead_clients` returns immediately when the watch list is empty and otherwise iterates only `_dead_clients.items()` (`nvflare/apis/impl/wf_comm_server.py:1024-1044`). The mapping requires a hook at the local `now` capture and one event after each actual loop iteration (`instrumentation-spec.md:110-112`). With two healthy clients and no reports, there is neither that `now` capture nor either client iteration. Even if a begin hook were emitted at function entry, the model would still require two nonexistent per-client steps. Trace has no silent route around them (`Trace.tla:544-570,913-920`), and full-state equality also requires the wrong pending set. **Required:** represent the empty-watch-list return and use actual watched-client iteration membership, preserving the real clock/lock boundaries. Align the hooks and add a complete healthy monitor/retirement trace to the later validation work. The existing three-event positive fixture stops before this problem.

- **Medium — The failed-client set is reset before its actual source boundary.** `FedAvgResetAggregation` replaces the entire aggregate record, including `failedClients`, with `EmptyAggregate` (`base.tla:60-63,117-122`). Its mapped hook is immediately after the helper/count reset in `FedAvg.run` (`instrumentation-spec.md:62`; `nvflare/app_common/workflows/fedavg.py:197-212`). However, `_current_failed_clients` is reset later inside `broadcast_model` (`nvflare/app_common/workflows/base_model_controller.py:150-158`), after `send_model` begins. The mapping explicitly identifies `aggr.failedClients` with that actual set (`instrumentation-spec.md:45`). If a dynamic-error round reaches the next round through the queue-empty/abort-observation ordering already modeled, the actual old failed-client set remains nonempty at the reset hook while Trace demands an empty set. **Required:** move this field's reset to a source-matching broadcast-preparation boundary and preserve its actual value in earlier snapshots. Do not repair the mismatch by synthesizing an empty observation ledger.

- **Medium — Result retries cover only loss observed after server handling.** `ClientLoseDispatchAck` is enabled only for an attempt already in `handled`, and `ClientRetryResult` requires `lost` (`base.tla:268-271,438-442`). Therefore the model cannot represent the client observing a send timeout while the original submission remains queued or its server callback is still executing. The real client supplies a timeout to `send_task_result` and retries on a failed send result without a server-handled prerequisite (`nvflare/private/fed/client/client_runner.py:590-637`; `nvflare/private/fed/client/client_run_manager.py:145-151`). `instrumentation-spec.md:105` explicitly restricts capture to known handled attempts, while the base retry comment says an old queued dispatch may still finish (`base.tla:266-267`), which the current state machine cannot express. **Required for broader S2 coverage:** separate the client's observed attempt outcome from the server dispatch stage, allowing a bounded timeout without discarding the original in-flight work or changing identity. Otherwise explicitly narrow the brief-coverage claim to post-handler ACK loss. No new transport implementation or fault reproduction is needed to identify this modeling gap.

- **Low — Several declared extensions have no enabled MC route.** Every `Limits_*` record sets both `snapshot=0` and `metric=0` (`MC.tla:262-284`), so `MCWFCommProtectBroadcastFailure` and `MCWeightedMetricFailure` cannot fire in any supplied MC configuration. The metric hunt exercises `metricPrep`, a different boundary. Also, all supplied configs have `RequiredSites = {}`, and at most one dead report is allowed with at least two clients, excluding the required-site and all-clients-dead policy branches. **Recommended:** add narrowly targeted configurations where these branches are intended coverage, or enumerate them as unexercised extensions in `brief-coverage.md`. The primary parameter-failure, metric-preparation, filter-retirement and minimum-sites mechanisms do have configured routes; this does not mean entire scenarios are absent.

- **Low — Branch-level annotations are less precise than the requested standard.** Compound decisions such as `WFCommDispatchSubmission` (`base.tla:282-293`) and `WFCommJobPolicyDecision` (`base.tla:499-507`) cite combined ranges once above the action. They do not attach separate references to live/terminal/receipt/history branches or all-dead/min-sites/required-sites branches. **Recommended:** add short branch-specific references and label model-only PC, normalization and environment assumptions explicitly. This would make the source-conformance review less dependent on reconstructing each range.
