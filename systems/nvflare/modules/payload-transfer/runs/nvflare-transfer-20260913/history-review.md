## Mechanism synthesis for the handoff

1. **Serving, materialization, and settlement are distinct facts.** #4247/#4270/#4327 show envelope delivery is too early to release sources; #4853 separates termination from success; #4865 requires terminal receiver truth; #4906 removes post-confirmation monitor delay. These establish contracts and historical risk but should not become requests to recreate their fixed predecessor states.
2. **Reference fanout is an identity-and-intersection problem.** #4708/#4712 fix per-requester idempotency and terminal replay; #4865 already implements declared-receiver membership and whole-payload quorum intersection. The supplied confirmed/explicit mode must keep those protections. Count-only and legacy modes need separately stated weaker contracts.
3. **Cancellation and independent monitors share source ownership.** #4736 moves callbacks outside the global table lock; #4865 registers serves, confirms and monitor budget passes in a transaction operation gate; #5097 adds acquired receiver cancellation spanning sibling refs. Current deep analysis should inspect genuinely new interleavings involving these paths, not assume they fail.
4. **Completion publication orders callbacks and attempted source release.** #4853 contains callback exception failures; #4865 shifts recording/waiter resolution after the release attempts and installs ownership/termination markers. A hung operation exceeding 60 seconds is an explicitly acknowledged exception to full draining. A release that raises is logged; successful physical cleanup is not promised by waiter completion.
5. **Activity scopes differ.** Transaction timeout has always been inactivity since any request, not an absolute deadline. #4736 adds byte/item monotonic-progress tracking for higher-layer wait policies; #4865 receiver budgets use each receiver activity across the whole transaction. Do not treat those as one clock or infer an absolute lifetime cap from TTL terminology.
