Source: NVFlare `53ba7ee567468ea7971dad4faccef13c6cb35dc2`. See `output/traces-r5/` for full replay receipts and `harness/RESULTS.md` for the executed workloads. No source behavior fix was applied; source changes are instrumentation.

Default startup policy is non-strict; admission/deploy enforce minimum/required sites, while non-strict start timeouts do not re-enforce them. The actual four workloads require site-1, use min_sites=1 except delayed_start=min_sites=2, max_jobs=2, and ListResourceManager with one GPU ID as an exclusive abstract unit. Hunt configs also use two units, strict startup and max_jobs=1. These configuration differences are explicit rather than implementation trace evidence for every hunt branch.

Its admission-exception bookkeeping and cancellation discussion are known context, not new discoveries. Reservations retain expiry; a missing acknowledgement does not establish a permanent leak, and expiry never reclaims an allocation transferred to a job.
