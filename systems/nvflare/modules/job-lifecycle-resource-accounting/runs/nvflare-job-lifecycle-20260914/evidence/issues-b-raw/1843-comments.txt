@Nicholas-B1 This could be caused by the machine resources you were trying to run this simulator job. When you run the command "./run_simulator.sh cifar10_fedavg 1.0 8 8", the first 8 is the number of threads to run the simulator. Which means there will be 8 threads to run the client jobs at the same time. The second 8 is the number of clients. I suspect that your machine does not have enough resources (CPU, memory, etc) to run 8 threads at the same time. Can you try lower this number and run it again? For example:

**./run_simulator.sh cifar10_fedavg 1.0 4 8**        //  Use 4 threads to simulate 8 clients run, client jobs will take turn to run

**./run_simulator.sh cifar10_fedavg 1.0 2 8**        // Further reduce the number of threads to simulate the clients run

Or even reduce the number of clients to run this experiment:

**./run_simulator.sh cifar10_fedavg 1.0 1 4**        // Use single thread to simulate 4 clients run, all the clients will be run one by one in turn

```
   git status
```
should tell you if you have code committed. If you do have uncommitted changes, git won't let you switch branch. you can either ignore all these changes: 
```
git reset --hard --<the last good commit hash>

or you can temp stash them for later use
```
git stash save WIP

```
git checkout 2.3

```

when you ready.  you can restore them back 

```
    git stash pop 
```
you might have conflicts if you already modified the same file.
