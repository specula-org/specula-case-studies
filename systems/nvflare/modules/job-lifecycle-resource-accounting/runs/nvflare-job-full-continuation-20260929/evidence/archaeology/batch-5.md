## Contracts established by the recent fixes (with test anchors)
1. **Abort intent is preserved** from client registration onward — during launch, `STARTING`, `STARTED`, and logically `STOPPED`-but-live — and results in termination once a handle exists (cb784550, a18489e4, 9b5dddfd; client_executor_test.py:55-146, 184-321).
2. **Single launch ownership**: at most one registration per job id; a failed launch removes only its own registration (a18489e4; client_executor_test.py:259-351).
3. **Terminal status ordering**: server status is published only after every active client's terminal outcome is applied, unless the outcome grace (default 900 s) expired (finalize from server outcome; never synthesize failure), the admin aborted, or an authoritative non-ABORTED server failure exists (46cfc517, 535373a0; job_runner_test.py:885-1063).
4. **Failure applied before barrier release**; late/duplicate outcome reports are idempotent `OK` (46cfc517; fed_server.py:938-956).
5. **Status precedence**: admin abort (`run_aborted`) > sticky `INFRASTRUCTURE_ERROR` > other failure codes > launcher `ABORTED`; a clean SJ `UPDATE_RUN_STATUS` never masks a recorded failure code (00589c73, 9b5dddfd; job_runner_test.py:586-768).
6. **Actionable client exits are reported**: generic RC 1 while `STARTING` => INFRASTRUCTURE_ERROR, while `STARTED` => EXCEPTION, unless the parent requested abort; `STOPPED`/UNKNOWN unchanged (196a3fdd, 52c966d1; client_executor_test.py:620-667).
7. **Heartbeat liveness**: a pending outcome protects client jobs only while the SJ has not failed (21253ddd; fed_server_test.py:508-550).
8. **Lifecycle accounting keyed by originating job id**; each `JOB_STARTED` is balanced by one `JOB_COMPLETED`/`JOB_ABORTED` of the same id (e1206061; job_runner_test.py:100-128, job_scheduler_test.py:346-372).
9. **Reservation lifecycle**: every token returned with `is_resource_enough=True` is consumed or cancelled; rejection bookkeeping must not raise before cancellation; a rejection "token" is a diagnostic, never a reservation (a6616c8a, 3bff3146; job_scheduler_test.py:493-545).
10. **Scheduling-pass robustness**: a malformed candidate is classified (BLOCK -> FINISHED_CANT_SCHEDULE) without interrupting later candidates; mandatory clients have set semantics (47684966; job_scheduler_test.py:432-490).
11. **Bounded completion**: archival retries bounded before status publication; the child always exits with its computed RC; artifacts ready before terminal status; an archive once written is never rewritten; packaging sources are read-only (71fbcaae, 6608949c, c7c4f1c5, efc47d47, 9b5dddfd; job_runner_test.py:299-583).
12. **Job-process teardown order**: reject new callbacks -> archive while F3 alive -> stop F3/Cell -> drain callbacks -> close security; terminal report precedes logout (9b5dddfd; job_process_cleanup_test.py, fed_client_base_test.py).
13. **Site-local error confinement** for RM exceptions (5e2283fb; scheduler_cmds_test.py:27-49).
