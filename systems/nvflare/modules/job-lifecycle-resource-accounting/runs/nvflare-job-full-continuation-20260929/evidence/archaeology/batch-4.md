## Possible unaudited sites at HEAD (read in code; NOT executed/reproduced)

- L6 [G1, candidate Critical: wrong terminal status]: abort vs run loop in pre-RUNNING states. `abort_job` writes FINISHED_ABORTED directly for SUBMITTED/DISPATCHED jobs (job_cmds.py:1058-1066). The runner checks then later writes, without a lock or compare-and-set: SUBMITTED check at job_runner.py:661, then `_deploy_job` (:669), then `set_status(DISPATCHED)` (:670); DISPATCHED check at :697, then `_start_run` (:703-708), then `set_status(RUNNING)` (:711). `set_status` is an unconditional merge (job_def_manager.py:459-481, `update_meta(replace=False)`). Store status stays SUBMITTED for the whole deploy, so an abort issued during deployment gets "Aborted the job ... before running it", after which :670 overwrites FINISHED_ABORTED and the job starts and runs. Same window between :697 and :711. The FAILED_TO_RUN write at :720 can likewise overwrite an abort. No HEAD test covers this; the only abort_job test is job_cmds_test.py:1960.
- L4 [G1, High: job stuck RUNNING]: no startup reconciliation. `update_unfinished_jobs`, `update_abnormal_finished_jobs` and `restore_running_job` (job_runner.py:744-796) and `pause_server_jobs` (server_engine.py:1093-1097) have no callers in nvflare/, tests/ or docs/, and `FederatedServer.deploy` sets HotState directly (fed_server.py:1216-1221). On graceful shutdown, `stop_all_runs` sets `ask_to_stop` immediately (job_runner.py:854-861), so the completion loop (:443) exits before publishing. Jobs left RUNNING stay RUNNING: abort returns "not running" (job_runner.py:802-811 via job_cmds.py:1071-1074) and delete refuses RUNNING/DISPATCHED (job_cmds.py:516-519). The CLI still expects ABANDONED (job_cli.py:2617,2785). Which commit dropped the last caller cannot be proven (pre-images missing); 4e090892's body lists `_turn_to_hot` removal.
- L3 [G2, Medium-High: admission blocked up to 900 s]: disable-client bypasses outcome resolution. `ServerEngine.disable_clients` (server_engine.py:620-644, via client_manager.py:117-140) removes tokens without `notify_dead_client`, unlike `logout_client` (fed_server.py:324-330 -> 1096-1106).
