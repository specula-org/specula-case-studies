# Instrumentation Guide — mongodb-session

Guide for Phase 3 (trace validation) to adjust instrumentation when validation reveals issues.

## Architecture

### Standalone scenario generator (active — generates all traces)

Because MongoDB's Bazel build requires a complex toolchain not available in this environment,
traces are generated by a standalone C++ state machine that faithfully implements the
`MongoDBSession.tla` spec. This is **not** the real MongoDB code — see the git patch section
below for real-code instrumentation.

**Binary**: `harness/build/session_scenarios`
**Source**: `harness/src/session_scenarios.cpp`
**Rebuild**: `cd harness/build && make -j4 session_scenarios`
**Re-run**: `bash harness/run.sh`

### Real MongoDB instrumentation (requires full MongoDB build)

**Header**: `harness/patches/tla_trace_session.h` → copy to
  `artifact/mongo-src/src/mongo/db/session/tla_trace_session.h`

**Patch**: `harness/patches/instrumentation.patch` — applies trace emit calls to:
- `session_catalog.cpp` — checkout, checkin, kill, kill release
- `session_catalog_mongod.cpp` — register kill change
- `logical_session_cache_impl.cpp` — refresh and reap lifecycle

**Apply**: `bash harness/apply.sh`

## How to add a new state field to an event

**In standalone generator** (`session_scenarios.cpp`):
Find the action function (e.g., `checkout_session`) and add a field to the `JsObj` call:
```cpp
te.emit("checkout_session", s,
    JsObj().s("checkoutOpCtx", "normal")
           .b("sessionInCatalog", ss.sessionInCatalog)
           .n("killsRequested", ss.killsRequested)
           .n("waiters", ss.waiters));  // ← add new field
```

**In real MongoDB code** (`tla_trace_session.h` macros):
Add to `TLA_SESSION_EMIT(...)`:
```cpp
TLA_SESSION_EMIT("checkout_session", lsid,
    {"checkoutOpCtx", jstr("normal")},
    {"sessionInCatalog", jbool(true)},
    {"killsRequested", jnum(sri->killsRequested)},
    {"waiters", jnum(session->_numWaitingToCheckOut)});  // ← add
```

## How to add a new event type

1. Add a new action function following the existing pattern in `session_scenarios.cpp`
2. Add the event to at least one scenario function
3. Add the event name to the `expected` set in `run.sh`
4. Rebuild and re-run: `bash harness/run.sh`

## How to move a capture point (before → after a state change)

Find the action function. State is captured AFTER the transition (post-state), which is already
the case for all current events. If you need pre-state, save the value before the state update:
```cpp
int old_kills = ss.killsRequested;
ss.killsRequested++;
te.emit("request_kill", s,
    JsObj().n("killsRequestedBefore", old_kills)
           .n("killsRequested", ss.killsRequested));
```

## Known issues requiring Phase 3 Trace.tla fix

### CheckoutForKill has no trace event

`checkout_for_kill_silent()` updates `checkoutOpCtx = "kill"` without emitting a trace event.
This is correct per the instrumentation spec ("kill checkout is inferred from the kill release
sequence"), but `Trace.tla` currently has no silent action for `CheckoutForKill`.

**Symptom**: TLC cannot match `kill_release_clear_checkout` because `checkoutOpCtx[s]` is
still `"none"` in the spec state when the event fires.

**Fix**: Add to `Trace.tla`'s silent actions:
```tla
SilentCheckoutForKill(s) ==
    /\ l <= Len(TraceLog)
    /\ sessionInCatalog[s] = TRUE
    /\ killTokenRegistered[s] = TRUE
    /\ killsRequested[s] > 0
    /\ checkoutOpCtx[s] = "none"
    /\ \/ IsSessionEvent("kill_release_clear_checkout", s)
    /\ CheckoutForKill(s)
    /\ UNCHANGED l
```
And add to `TraceNext`:
```tla
\/ \E s \in Session : SilentCheckoutForKill(s)
```
