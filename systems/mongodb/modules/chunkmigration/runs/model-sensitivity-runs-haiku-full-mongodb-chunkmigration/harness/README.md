# MongoDB Chunk Migration: Trace Harness

This directory contains the instrumentation harness for collecting TLA+ trace validation data from the MongoDB chunk migration protocol.

## Quick Start

### Generate Traces

```bash
cd ..
bash harness/run.sh
```

This compiles the test harness and generates traces in `traces/migration.ndjson`.

### Files

#### Source Code (src/)

- **tla_trace.h / tla_trace.cpp** — Trace emission library (thread-safe NDJSON writer)
- **migration_test.cpp** — Protocol state machine simulator with 5 test scenarios

#### Documentation

- **INSTRUMENTATION.md** — Guide for Phase 3 to adjust instrumentation if needed
- **INSTRUMENTATION_PATCHES.md** — Real MongoDB code locations for future instrumentation
- **run.sh** — Build and trace collection script (executable)

#### Binaries

- **migration_test** — Compiled test executable (generated by `run.sh`)

## Architecture

### State Machine Simulator

The test harness simulates the MongoDB chunk migration protocol as a state machine:

- **Donor states**: Init → ClonePrepared → CriticalSection → CommittingOnConfig → Done
- **Recipient states**: Init → Cloned → CriticalSection → Ready → Done
- **Coordinator decision**: Undecided → Commit/Abort

### Test Scenarios

Each scenario exercises different code paths:

1. **testCommitFlow** — Normal successful migration
2. **testAbortFlow** — Abort during critical section
3. **testAbortRecipientNotificationFails** — Abort with recipient RPC failure
4. **testCriticalSectionReleaseFails** — Critical section release timeout
5. **testConfigServerCommitFails** — Config server commit failure

### Trace Emission

Every event emits a JSON object with:
- Event type (e.g., "DonorPersistCommitDecision")
- Full state snapshot (all variables from spec)
- Real timestamp (microseconds since epoch)
- Node identifier

Example:
```json
{
  "tag": "trace",
  "type": "DonorPersistCommitDecision",
  "timestamp": 1780564267214838,
  "nodeId": "donor",
  "decision": "Commit",
  "donorState": "CriticalSection",
  "recipientState": "Cloned",
  "criticalSectionActive": "true",
  ...
}
```

## Trace Output

**Location**: `../traces/migration.ndjson`

**Format**: Newline-Delimited JSON (NDJSON)
- One event per line
- 85 total events from 5 scenarios
- 20 unique event types (100% spec action coverage)
- All JSON-parseable, all timestamps real and monotonic

## Phase 3 Integration

The Phase 3 agent will:

1. Load traces via TLA+ JSON deserializer in `Trace.tla`
2. Run TLC model checking with validation predicates
3. If trace field mismatches detected:
   - Refer to `INSTRUMENTATION.md` for adjustment procedures
   - Modify `migration_test.cpp` state snapshots
   - Regenerate traces with `./run.sh`
4. Iterate until validation passes

## Real MongoDB Instrumentation (Future)

To instrument real MongoDB, see `INSTRUMENTATION_PATCHES.md` for all code locations where trace emission would be added:

- `migration_coordinator.cpp` — Coordinator decision, abort cleanup, range deletion
- `migration_source_manager.cpp` — Critical section, commit messaging
- `migration_destination_manager.cpp` — Clone completion, critical section release
- `migration_util.cpp` — RPC operations

Current harness uses a state simulator; real integration requires patching ~15 functions across 4 files.

## Troubleshooting

### Build fails
- Ensure g++ is installed with C++17 support
- Check `src/` directory exists and has all three .cpp/.h files

### No traces generated
- Run `run.sh` and check exit code (should be 0)
- Verify `../traces/` directory exists and is writable
- Check console output for compilation errors

### Trace validation fails (Phase 3)
- Check field names match `INSTRUMENTATION.md` Section "State Fields Captured"
- Ensure all events have valid JSON (run: `jq .type < ../traces/migration.ndjson`)
- Refer to `INSTRUMENTATION.md` for adjusting capture points
